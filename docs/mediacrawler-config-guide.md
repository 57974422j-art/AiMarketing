## 一、系统定位与架构总览

### 1.1 是什么

MediaCrawler 是 AiMarketing 平台的 **数据采集引擎**，负责从各社交媒体平台抓取公开内容（视频搜索、评论、用户画像、热门话题），为线索采集和行业洞察提供数据源。

## 二、服务配置详解

### 2.1 服务器环境要求

```
操作系统: Linux (推荐 Ubuntu 20.04+)
Python:   >= 3.9
Node.js:  >= 18 (已有, Next.js 运行环境)
内存:     建议 >= 2GB 给 MediaCrawler (Playwright Chromium)
磁盘:     >= 10GB (浏览器缓存 + Cookie + 数据临时存储)
网络:     需能访问目标平台(抖音/小红书等)，可能需要代理
```

### 2.2 安装步骤

```bash
# ===== 第一步：安装 Python 环境 =====
python3 --version          # 确认 >= 3.9
pip3 --version

# ===== 第二步：安装 Playwright 浏览器 =====
pip3 install playwright
playwright install chromium    # 下载 Chromium (~130MB)

# ===== 第三步：克隆 MediaCrawler 项目 =====
cd /opt
git clone https://github.com/NanmiCoder/MediaCrawler.git
cd MediaCrawler

# ===== 第四步：安装 Python 依赖 =====
pip3 install -r requirements.txt
# 核心依赖:
#   playwright        # 浏览器自动化
#   httpx             # HTTP 客户端
#   orjson / loguru   # JSON处理/日志

# ===== 第五步：验证安装 =====
cd /opt/MediaCrawler
python3 -c "import media_crawler; print('✅ 导入成功')"
```

### 2.3 环境变量配置

在 AiMarketing 的 `.env.local` 中配置：

```bash
# ===== MediaCrawler 核心配置 =====

# MediaCrawler 安装路径（默认 /opt/MediaCrawler）
MEDIA_CRAWLER_PATH=/opt/MediaCrawler

# Python 可执行文件路径（默认 python3）
PYTHON_BIN=python3

# 自动化引擎类型（支持多引擎逗号分隔）
AUTOMATION_ENGINE=mediacrawler
# 可选值: mediacrawler | douyin-official | q1-coordinates | fingerprint
# 例: AUTOMATION_ENGINE=mediacrawler,q1-coordinates
```

### 2.4 Cookie 配置（关键）

MediaCrawler 需要平台的登录 Cookie 才能获取完整数据。有两种方式：

#### 方式 A：扫码登录（推荐，首次配置使用）

```
操作流程:

1. 服务器端执行（需要有图形界面或 X11 转发）:
   cd /opt/MediaCrawler
   python3 main.py --login --platform douyin

2. 弹出 Chromium 浏览器窗口 → 显示抖音二维码

3. 用手机抖音 APP 扫码确认

4. 登录成功后 Cookie 自动保存到:
   /opt/MediaCrawler/data/cookies/douyin_xxxx.json

5. AiMarketing 通过 API 管理 Cookie:
   POST /api/mediacrawler/login  { platform: "douyin", action: "status" }
   → 查看 Cookie 是否有效/过期时间
```

#### 方式 B：手动导入 Cookie

适用于无图形界面的服务器：

```
1. 从浏览器 DevTools 复制 Cookie (F12 → Network → 复制 Cookie 字段)

2. 通过 API 导入:
   POST /api/mediacrawler/cookies
   {
     platform: "douyin",
     cookies: [
       { "name": "ttwid", "value": "xxx", "domain": ".douyin.com" },
       { "name": "passport_csrf_token", "value": "xxx", ... }
     ]
   }

3. 或直接写入 MediaCrawler 的 data 目录
```

#### Cookie 生命周期管理

```
Cookie 有效期:
  · 抖音: 约 7-30 天（取决于活跃度）
  · 小红书: 约 7 天
  · 快手: 约 15-30 天

自动检测机制:
  ┌──────────────────────────────────────┐
  │  每次调用 crawl() 时                  │
  │    ↓                                  │
  │  如果返回 403 / 登录提示              │
  │    ↓                                  │
  │  自动标记 cookie_status = "expired"   │
  │    ↓                                  │
  │  前端显示: "Cookie 已过期，请重新登录"  │
  │    ↓                                  │
  │  用户重新扫码 → 更新 Cookie            │
  └──────────────────────────────────────┘
```

### 2.5 IP 代理池配置

当爬取频率较高时需要配置代理避免 IP 封禁。

#### 配置位置

代理池数据存储在项目根目录 `.proxy-pool.json` 文件中（非数据库）。

#### 配置结构

```json
{
  "proxies": [
    {
      "id": "px_1717xxxx_abc123",
      "host": "203.0.113.50",
      "port": 8080,
      "protocol": "http",
      "username": "user1",
      "password": "pass1",
      "enabled": true,
      "label": "电信住宅IP-上海",
      "region": "CN",
      "type": "residential",
      "maxUses": -1,
      "usedCount": 23,
      "lastUsedAt": "2026-06-07T10:30:00Z",
      "lastTestAt": "2026-06-07T08:00:00Z",
      "testStatus": "ok",
      "testLatencyMs": 350,
      "createdAt": "2026-06-01T00:00:00Z"
    }
  ],
  "settings": {
    "autoRotate": true,         // 自动轮换（每 N 次请求换一个IP）
    "rotateInterval": 10,       // 轮换间隔（请求数）
    "failoverOnBan": true,      // 被封禁自动切换到下一个
    "banThreshold": 3,          // 连续失败 N 次判定为被封
    "globalEnabled": false      // 全局开关（默认关闭，手动启用）
  }
}
```

#### 代理类型选择建议

| 类型 | 适用场景 | 推荐供应商类型 | 成本 |
|------|---------|--------------|------|
| **datacenter** (数据中心) | 大批量爬取、速度优先 | 云服务商弹性IP | ¥1-5/IP/天 |
| **residential** (住宅) | 反爬严格平台（抖音）、需长期稳定 | 代理服务商 | ¥5-15/IP/天 |
| **mobile** (手机) | 移动端特有内容、最防封 | 4G/5G 代理池 | ¥10-30/IP/天 |

#### 代理管理 API

| 方法 | 操作 | 示例 |
|------|------|------|
| `GET` | 查看所有代理+统计 | `?` |
| `POST` | 添加单个/批量代理 | `{ host:"1.2.3.4", port:8080, ... }` |
| `DELETE` | 删除单个/清全部 | `?id=px_xxx` 或 `?clear=true` |
| `PATCH test` | 测试单个连通性 | `{ action:"test", id:"px_xxx" }` |
| `PATCH test-all` | 批量测试所有启用的 | `{ action:"test-all" }` |
| `PATCH toggle` | 启用/禁用 | `{ action:"toggle", id:"px_xxx" }` |
| `PATCH settings` | 更新轮换策略 | `{ action:"settings", settings:{...} }` |

#### 代理自动轮换逻辑

```
每次 crawl() 调用时:
  
  1. getProxyForRequest()
     ↓ 读取 .proxy-pool.json
     ↓ 检查 globalEnabled?
     
  ┌─ 全局未启用 → 返回 null（不使用代理，直连）
  │
  └─ 全局已启用 ↓
     ↓ 筛选 enabled && testStatus != 'fail'
     ↓ 按 usedCount 升序排序（选最少使用的）
     ↓ 构建代理URL → 返回
     
  2. crawl() 使用该代理发起请求
     ↓
  3. markProxyResult(proxyUrl, success/failure)
     ↓ usedCount++
     ↓ 写回 .proxy-pool.json
     ↓ 如果连续失败 >= banThreshold → 自动标记 fail
```

### 2.6 引擎调度配置

通过 `AUTOMATION_ENGINE` 环境变量控制当前激活的数据采集引擎：

```typescript
// automation-providers.ts 中的引擎选择逻辑

function getActiveEngines(): AutomationEngine[] {
  const raw = process.env.AUTOMATION_ENGINE || ''
  // 支持逗号分隔的多引擎: "mediacrawler,q1-coordinates"
  return raw.split(',').map(s => s.trim()) as AutomationEngine[]
}

// 调用时的优先级链:
// mediacrawler (爬虫) → douyin-official (官方API) → 返回错误提示
```

## 三、数据流：从采集到存储

### 3.1 完整数据流水线

```
                        数据采集流水线
                        
  用户触发采集任务
       ↓
  POST /api/lead-collector  { action: "run-task", taskId: 5 }
       ↓
  ┌──────────────────────────────────────────────────┐
  │  Phase 1: 搜索                                    │
  │                                                   │
  │  关键词: ["美业引流", "美容院推广"]                 │
  │       ↓                                          │
  │  dispatchEngine({ action: 'extract', ... })       │
  │       ↓                                          │
  │  engine-dispatcher → 判定为"读操作"               │
  │       ↓                                          │
  │  automation-providers.douyinSearchVideo()         │
  │       ↓                                          │
  │  viaMediaCrawler('search', { keyword, count })   │
  │       ↓                                          │
  │  crawler-client.ts → spawn Python 进程            │
  │       ↓                                          │
  │  MediaCrawler DouyinSearch.search_videos()        │
  │       ↓                                          │
  │  返回: Video[] (20条视频)                         │
  └──────────────────────┬───────────────────────────┘
                         ↓
  ┌──────────────────────────────────────────────────┐
  │  Phase 2: 评论深挖                                 │
  │                                                   │
  │  对每个视频 (Top 10):                              │
  │    viaMediaCrawler('comments', { url, count:50 }) │
  │       ↓                                          │
  │  返回: Comment[] (每视频50条评论)                  │
  │                                                   │
  │  总计: 20视频 × 50评论 = 1000 条评论               │
  └──────────────────────┬───────────────────────────┘
                         ↓
  ┌──────────────────────────────────────────────────┐
  │  Phase 3: AI 线索提取                              │
  │                                                   │
  │  每条评论 → LLM 分析:                             │
  │    · 是否包含购买意向？                            │
  │    · 是否包含联系方式？(手机/微信/VX)              │
  │    · 意向度评分 (0-1)                             │
  │                                                   │
  │  输出:                                           │
  │  {                                               │
  │    content: "这家效果怎么样？想预约",               │
  │    contactInfo: null,                            │
  │    intentScore: 0.75,                             │
  │    intentType: "purchase_inquiry"                │
  │  }                                               │
  └──────────────────────┬───────────────────────────┘
                         ↓
  ┌──────────────────────────────────────────────────┐
  │  Phase 4: 入库存储                                 │
  │                                                   │
  │  高意向线索 (intentScore > 0.5):                  │
  │    → prisma.lead.create() → Lead 表               │
  │                                                   │
  │  原始数据 (视频+评论):                             │
  │    ⚠️ 当前: 不入库，仅内存传递                      │
  │    🔮 规划: 应存入 CrawledData 表（见第四章）       │
  └───────────────────────────────────────────────────┘
```

### 3.2 当前数据存储位置

| 数据类型 | 存储位置 | 格式 | 保留策略 |
|---------|---------|------|---------|
| **线索 (Lead)** | SQLite (`prisma`) `Lead` 表 | 结构化 | 永久保存（手动删除） |
| **采集任务 (CollectionTask)** | SQLite `CollectionTask` 表 | 结构化 | 永久保存 |
| **原始视频数据** | ❌ **不存储** | - | 仅当次请求内存中使用 |
| **原始评论数据** | ❌ **不存储** | - | 仅当次请求内存中使用 |
| **用户画像** | ❌ **不存储** | - | 仅实时返回给前端 |
| **热门话题** | ❌ **不存储** | - | 仅实时返回给前端 |
| **Cookie** | `/opt/MediaCrawler/data/cookies/*.json` | JSON | 由 MediaCrawler 管理 |
| **代理池配置** | 项目根目录 `.proxy-pool.json` | JSON | 持久保存 |

### 3.3 当前数据库 Schema（相关部分）

```prisma
// ========== 线索表 ==========
model Lead {

| **线索总数** | Lead 表记录数 | Lead.count() | 实时 |
| **高意向线索** | `WHERE intentScore >= 0.7 AND status = 'new'` | Lead 查询 | 实时 |

| **采集成功率** | 成功请求数 / 总请求数 | 采集日志 | 实时 |
| **平均响应时长** | 从发起到收到数据的平均耗时(s) | 采集日志 | 实时 |

### 5.4 交叉分析与联动

```
页面间数据联动示例:

  场景: 在视频库中看到一条爆款视频
       ↓ 点击进入视频详情
       ↓ 看到"关联线索"区域有 5 条高意向评论
       ↓ 点击其中一条评论者头像
       ↓ 跳转到用户画像页，看这个人的全部历史评论
       ↓ 发现他在 3 个不同视频下都问过价格 → 高价值潜客
       ↓ 右键"加入重点跟进名单"

实现技术:
  · 每个详情页携带 source 回调参数
  · 返回时恢复之前的筛选状态 (URL query 保持)

### 6.4 常见问题 FAQ

```
Q1: 采集出来的数据为什么比我在抖音APP上搜到的少？
A: MediaCrawler 通过网页版接口采集，部分数据可能因反爬机制
   或隐私设置无法获取。另外采集数量受限于你设置的参数
   (每关键词20个视频)。如果需要更多数据，可以在任务设置中调大数值。
   
Q2: 意向度评分准不准？
A: AI 意向度判断基于 LLM 大语言模型，准确率约 70-85%。
   建议将 ≥0.7 的作为高优先级处理，0.5-0.7 的人工复核，
   <0.5 的一般可以忽略或作为参考。随着使用积累，AI 会越来越准。

Q3: Cookie 经常过期怎么办？
A: 这是平台的正常安全策略。通常:
   - 抖音 Cookie: 7-30天
   - 小红书 Cookie: 约7天
   过期后系统会提示，需要管理员重新扫码登录。
   如果频繁过期，可能是采集频率过高触发了风控，建议:
   a) 降低采集频率
   b) 开启IP代理池
   c) 增加请求间隔

Q4: 能不能采集私信/群聊内容？
A: 目前不支持。MediaCrawler 只能采集公开可见的内容
   (公开视频、公开评论、公开用户信息)。私信属于私密数据，
   需要通过其他方式获取 (如 AI Agent + 设备自动化)。

Q5: 导出的 Excel 能不能自定义格式？
A: 可以。导出中心支持:
   - 自定义选择导出字段
   - 上传自定义 Excel 模板
   - 选择是否包含统计汇总页
   后续版本还将支持"保存导出模板"功能，一次配置反复使用。

Q6: 采集的数据量大了以后会不会卡？
A: 我们做了分层优化:
   - 数据库: SQLite + 索引优化
   - 前端: 虚拟滚动 + 分页加载 (每页 20 条)
   - 搜索: 先用数据库查询，后期接入专业搜索引擎
   一般 10 万条以内数据不会有明显的卡顿感。
```

### 7.6 定时采集规划

当前采集是**手动触发**（用户点"开始采集"）。规划增加定时能力：

```typescript
// 定时采集配置 (可在 CollectionTask.schedule 中扩展)

type ScheduleConfig = {
  type: 'manual'        // 手动触发（当前）
       | 'interval'     // 固定间隔 (每N小时)
       | 'cron'         // Cron 表达式
       | 'smart';       // 智能调度（根据平台活跃时段）
  
  intervalHours?: number;     // interval 模式: 间隔小时数
  cronExpression?: string;     // cron 模式: "0 9 * * *" (每天9点)
  smartWindows?: string[];     // smart 模式: 活跃时间段 ["09:00-12:00", "19:00-23:00"]
  maxRunsPerDay?: number;      // 每日最多执行次数 (防超量)
};

// 实现方式选项:
// 
// 方案 A: Next.js API Routes + node-cron (简单)
//   · 在 API Route 中启动 cron job
//   · 缺点: 服务重启丢失；不适合 serverless
//
// 方案 B: PM2 + 独立 cron 进程 (推荐)
//   · scripts/collection-scheduler.js
//   · PM2 管理: pm2 start collection-scheduler --name "crawler-sched"
//   · 优点: 独立进程，不影响 Web 服务
//
// 方案 C: 外部 Cron (系统 crontab + curl)
//   · crontab: */3 * * * * curl -s http://localhost:3000/api/...
//   · 最简单可靠
```

### 10.3 常见问题排查

| 症状 | 可能原因 | 解决方法 |
|------|---------|---------|
| `SPAWN_ERROR: 无法启动` | Python 未安装或路径错误 | 检查 `which python3`; 设置 `PYTHON_BIN` |
| `Import Error` | 依赖未装全 | `pip3 install -r requirements.txt` |
| 退出码非 0 + `403` | Cookie 过期 | 重新扫码登录 |
| 退出码非 0 + 超时 | 网络慢或被反爬 | 减少count参数；开启代理 |
| `TIMEOUT 60000ms` | 目标平台响应慢 | 增大 timeout 或减少数据量 |
| 代理 `testStatus: fail` | 代理失效 | 更换代理或联系供应商 |
