## 1. 不返回链接 → 前台直接播放

### 现状（实测输出）
```
MAKE_VIDEO_DONE:本地成片已完成 ✅（配音 + 字幕 + 画面）
已存入个人仓库：20260919_001.mp4
下载：https://aimarketing-1.oss-cn-hangzhou.aliyuncs.com/storage/1/20260919_001.mp4?OSSAccessKeyId=...&Expires=...&Signature=...
```
**四个坏处**：① 长、丑、吵 ② 签名链接**24h 过期**（过期后点不开）③ 点了是**下载**不是播放 ④ 把 OSS 直链暴露给用户。

### 方案（推荐 W2）
| | 做法 | 改动 |
|---|---|---|
| **W1** | 消息只回"已完成"，前端用 **`<video>` 卡片**播放（源 = `/api/storage/file?name=20260919_001.mp4&persist=1`，走我们自己的接口，不暴露 OSS） | `route.ts` 文案 + `page.tsx` 卡片 |
| **W2（推荐）** | W1 + 卡片上带 **「👇 下载到本地」「📤 去发布」** 两个按钮；下载走客户端镜像（`storage:mirror`，和你已有的本地仓库机制一致） | 同 W1 + 两个按钮 |

**要点**：签名链接仍然生成（客户端镜像/发布要用），但**只走内部，不进对话文案**。

## 2. 画面质量 & 画面来源（你说的"不是 AI 做的"）

### 事实澄清
这次你点的是 **🎞 素材合成**，所以：
- **画面 = 你仓库里的 10 张图**（视觉模型看过、AI 排成 5 个镜头）
- **文字/字幕/配音 = 系统做的**
- **没有任何一帧是 AI 生成的** ← 所以你感觉"不是 AI 做的"，**完全正确**

### 三条质量路线（成本差 100 倍，必须选）

| 路线 | 画面怎么来 | 单条成本 | 观感 | 现状 |
|---|---|---|---|---|
| **A 素材合成**（现在） | 你的图 + 大字 + 转场 | **≈4 点** | 像**精修 PPT 动效**；素材好则不错，素材平则平淡 | ✅ 已实现，但**动效太简陋**（只有淡入/位移） |
| **B 素材 + AI 混合** | 有合适素材用素材，关键镜用 AI 生成视频 | 几十~几百点 | 明显更像"宣传片" | ❌ 未实现（要接 AI 逐镜生成） |
| **C 全部 AI 生成** | 每镜文生视频 | 上千点 | 最像"真视频"，但**贵且不可控**（AI 会跑偏） | ❌ 未实现 |

### 我的建议（先提升 A，再做 B）
1. **A 升级（性价比最高，几档就能看出差别）**
   - **Ken Burns 动效**（图片缓慢推拉/平移）→ 立刻有"视频感"
   - **镜头节奏**：按配音断句卡点切镜（现在镜头时长和配音不对齐）
   - **字幕动效**：逐句出现 + 关键词高亮
   - **转场**：叠化/推进，替换现在的硬切
   - **配色/底板**：从素材里取主色做底板（视觉统一）
2. **B 混合**（在 A 稳了之后接）：只把**首镜**和**结尾镜**用 AI 生成（钩子和 CTA 最重要），中间用素材 → 成本可控
3. **C 全 AI**：等 B 跑顺再说

⚠️ **一句实话**：**A 路线的天花板是"素材质量"** —— 如果仓库里都是界面截图/封面图，做出来的就是"图文播报"；**要"电影感"必须走 B/C**。

## 3. 横竖屏 / 分辨率（你提的"横屏被收窄"）

### 现状（bug 定位）
```ts
// chat/route.ts（我写的）
{ plan: JSON.stringify({ size: [1080, 1920], fps: 25, shots: vd.shots }) }
//                                    ↑ 写死竖屏
```
→ **横图（16:9）被塞进 9:16 画布** → FFmpeg 按最小边缩放 → 左右被裁 / 或被压扁。

### 方案（推荐 P3：自动判断 + 可覆盖）
| | 做法 | 优点 | 缺点 |
|---|---|---|---|
| P1 | 固定竖屏 9:16，横图**模糊填充**（背景放大模糊 + 居中完整图） | 不裁切、不丢内容 | 上下有虚化边（观感尚可） |
| P2 | 让用户每次选（竖屏/横屏） | 可控 | 多一步操作（违背"一键出发"） |
| **P3（推荐）** | **按素材多数比例自动定画布**：竖图多→9:16；横图多→16:9；再按 P1 规则填充不裁切。卡片上标明"画布：横屏（因你素材多为横图）"，用户可一句话改 | 零操作 + 不裁切 + 可覆盖 | 需要一次素材宽高探测 |
| P4 | 每镜自适应（横镜横屏区、竖镜竖屏区） | 最贴素材 | 成片内比例跳变，观感乱（不推荐） |

**实现要点**：需要读每张图的宽高（FFmpeg `ffprobe` 或读 JPEG 头），我在素材层加一个 `probeMaterialSizes()` 就够。
