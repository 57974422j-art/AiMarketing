## 1. ★ 用户的核心定案（最高优先级，不要违背）

**用户原话**：
> 「现在成片和帮我发一个视频都是状态机。**用本地成片帮我做一条视频本来也是一个状态机下 3 个模式**。但因为 AI 老搞错，加了 AI 制片就把我已经基本跑通的素材合成逻辑又搞乱了。**所以我要把一个拆成 3 个。三个状态机不共享。单独卡片。素材合成是素材合成，AI 制片是 AI 制片，素材+AI 是素材+AI。**」

> 「**不要设计公用层**……最怕你们设计了共用，不如不拆，出问题都不能用。」

### 三条线对照表

| # | 线名 | 后端实现 | 草稿 tag | 日志前缀 | 入口词（前台也会显示） | 画面来源 |
|---|---|---|---|---|---|---|
| 1 | **素材智能成片** | `src/app/api/agent/chat/route.ts`（**原逻辑，用户说"先不动"**） | `vf_draft` | `[VF]` | `用本地成片帮我做一条视频` | 用户仓库的图 + Ken Burns |
| 2 | **AI 制片** | `src/lib/agent/vf/vf-aivideo.ts` | `vf_draft_ai` | `[VF-A]` | `AI 制片帮我做一条视频` | **全部由 AI 生成**（MiniMax H3） |
| 3 | **素材+AI 创作** | `src/lib/agent/vf/vf-mix.ts` | `vf_draft_mix` | `[VF-X]` | `素材+AI创作做一条视频` | AI 只画"该动的镜"，其余用素材 |

### 分派顺序（`route.ts` 约 L2785 起，顺序即优先级）

```ts
① if (await shouldTakeOverMixLine(prisma, uid, msg))  → handleMixLine(...)   // 词最具体，放最前
② if (!vfMixHandled && await shouldTakeOverAiLine(...)) → handleAiLine(...)
③ if (!vfMixHandled && !vfAiHandled && (vfIntent || VIDEO_DRAFT.has(uid))) → 素材智能成片（原逻辑）
```
> 两条新线没接管时，`vfMixHandled`/`vfAiHandled` 恒为 `false`，素材智能成片行为与之前完全一致。

### 隔离的三条铁律（改这片代码前必读）

1. **两个新文件零 `import` 项目内部路径** —— prisma / 工具函数全部由 `ctx` 注入（曾有版本写了 `@/lib/prisma`，项目里没这个路径 → build 失败）
2. **草稿 tag 分开**（`vf_draft` / `vf_draft_ai` / `vf_draft_mix`）—— **绝不能合并**
3. **各自内部绝不 throw** —— 异常转成人话返回 + 写日志；否则连累其它两条线

### 提交 3：`479d917c` —— **表单按字段认领归属**（关键修复，见下）

**根因（用户第二次数出"还是接错"）**：三条线的卡片**都发 `VF_FORM:` 前缀**，所以光看前缀分不出是哪条线：

```
素材线   page.tsx L637 → VF_FORM:{aspect,dur,voice,source,topic,script,bgm,theme,uploaded?}
AI 卡1   page.tsx L686 → VF_FORM:{topic, uploaded?}
AI 卡2   page.tsx L731 → VF_FORM:{script, aspect, dur, style}
```
上一轮只加了「入口词排除」——**但点「🚀 开始出片」发出的 `VF_FORM:{"source":"repo",...}` 不含任何入口词**，排除不生效 → AI 线凭残留草稿接管 → 用户看到「AI 制片：请点开始出片」。

**改法**：`shouldTakeOverAiLine` / `shouldTakeOverMixLine` 增加**表单字段认领**：
```ts
const _fm = m.trim().match(/^VF_FORM:(\{[\s\S]*\})/)
if (_fm) {
  const f = JSON.parse(_fm[1] || '{}')
  // 带 source/voice/theme/bgm = 素材线独有字段 → 这两条线绝不接管
  if (('source' in f) || ('voice' in f) || ('theme' in f) || ('bgm' in f)) return false
}
```

### 各阶段失败长什么样（对照表）

| 日志关键字 | 含义 | 处理 |
|---|---|---|
| `[H3] 中转 提交失败: HTTP 403` | **中转站 key 无效** | 换有效 key（官方会自动兜住，片子还是能出） |
| `[H3] ✅ 第 N 镜 OK  官方` | 降级官方成功 | 正常（但每镜白试一次中转，白等） |
| `[H3] ⚠️ 第 N 镜 AI 生成失败 → 该镜回退用原画面` | 单镜失败 | **不整片挂**，正常兜底 |
| `[MAKE] ⚠️ 没有任何 AI 片段生成成功 → 自动回退素材合成` | 全失败 | 查官方 H3 key |
| `[TTS] 引擎=dashscope`（或 minimax/silicon/volcano） | 实际用的配音引擎 | 正常（引擎顺序见 `.env.local` 的 `VF_TTS_ORDER`） |
| `[TTS] ⚠️ 全部引擎都失败` + `[MAKE] ⚠️ 无配音，出无声片` | 配音全挂 | 查 TTS key；片子只剩 BGM |
| `[VF] ⚠️ 未知配方卡「x」→ 降级为 title 卡` | AI 自造卡型 | 正常（不会整片挂） |
| `[分镜门禁] N 镜 / 覆盖 X% → 不给确认出片` | 字幕覆盖率 < 80% | 卡片会给「🔄 重试分镜」/「▶️ 先出字幕版」 |
| `MAKE_VIDEO_FAIL:...` | 整片失败 | 看返回里附的 tail 最后几行 |
| `MAKE_VIDEO_TASK:vf...` | **正常**（已入队） | 之后用「查询进度」或问"视频做得怎么样了" |

### 环境/机制类的坑（这几条最容易误判）

| 现象 | 真因 |
|---|---|
| **"改前端了但没生效"** | `src/` 改动必须**部署构建**才生效；`scripts/video-factory/*.py` 改动 `git reset` 即生效（**不用 build**）。**后端新、前端旧 = `page.tsx` 没进那次提交** |
| **"打开登记页显示未登录"** | 不是登录态丢：`bu:check` 读不到 Cookies 时**不得谎报成功**（已修）；且"登记"打开的是平台**官网首页**（不是纯登录页） |
| **Chrome 开着时读不到 Cookies** | Windows 下 Chrome **独占锁** Cookies → 只能走 CDP `9222` 的 `Storage.getCookies`（普通读/复制/powershell 复制全部失败） |
| **AI 制片"没返回"** | 多半是**正常在跑**（H3 逐镜生成是分钟级，6 镜十几~几十分钟）；先看任务 JSON 的 `status` |
| **GIT 相关** | 禁止 `git add -A`（2026-09-18 误提交 `temp/` 26146 个文件 → `.git` 涨到 895MB）；只用**按路径白名单** `git add` |
