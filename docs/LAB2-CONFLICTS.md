# LAB2 提示词自相矛盾清单（2026-11-02 审计）

> 用户要求：「最好你自己分析一下 prompt 和你现有这些设置，看看是否还有什么自相矛盾的」
> 结论：**找到 10 处矛盾**，其中 4 处是「它为什么总贴着下限走」的直接原因。

## 🔴 致命矛盾（直接导致「偷懒」）

### ① 装饰密度「多」vs 三道闸「至少 3 类」

```
L196  三道闸③：每段**至少 3 类**装饰        ← 写在【硬底线】里，权重最高
L458  装饰密度=多：每段 **5~6 类**           ← 写在【本版设定】里，权重低
        ↓
它选「3 类」（更硬的那条）
        ↓
实测（用户选"多"）：AI 自报 [4,3,4,3,4,3] = 平均 3.5 类
```

⇒ **这是「档位设定被硬底线吃掉」的典型。**

### ② TEXTURE「不能干净」vs 情绪空镜「不加装饰」

```
L46   DIRECTOR：「干净得像模板 = 不合格」⇒ 必须加质感（颗粒/暗角/扫描线）
CONTENTS.mood：「❌ 不用装饰 / 不加染色 / 极简文字」
        ↓
选 mood 时两条直接打架 ⇒ 它只能二选一
```

### ③ 「禁整图盖深色层」vs「暗角/扫描线本质就是盖」

```
L123  ❌ 禁在整张图上盖半透明深色层来"突出文字"
L76   ② 带色暗角：radial-gradient 边缘压 .18~.25   ← 这就是"整图盖半透明"
L78   ③ 扫描线：全屏覆盖                          ← 也是
        ↓
⇒ 三条互相打架
（后来补了「不许盖照片」，但「暗角」本身就是盖 ⇒ 没根治）
```

### ④ 「CSS 最省」vs「只用 CSS 算偷懒」

```
L178  动效：CSS（最省）→ 原生 JS（优先）
L187  ④ 不许只用 CSS（canvas 0 次 + three 0 次 ⇒ 你在偷懒）
        ↓
一边说 CSS 最省，一边说只用 CSS 是偷懒
        ↓
而且 L184「① 必须用 SVG」 ⇒ 用了 SVG 但没用 canvas/three，按 ④ 还是偷懒
```

## 🟠 次要矛盾（造成混乱）

### ⑤ 「必须用 SVG」vs「promo 类型用 CSS 做放射线/印章」

```
L184  ① 必须用 SVG（描边字/图标/图表/引线）
CONTENTS.promo：放射线条纹 + 印章
        ↓
放射线用 CSS conic-gradient 最省、印章用 CSS 也行
        ↓
⇒ 它纠结「这算不算违反 ①」
```

### ⑥ 「主体占短边 40~65%」说两遍

```
L188  ⑤ 不许元素太小（主体占短边 40~65%）
L195  三道闸② 主体够大（40~65%）
        ↓
⇒ 重复占空间，不增加信息
```

### ⑦ 「算公式」vs「别算，用 flex」

```
L146  公式：字数 × 字号 × 1.06 + 边距×2 ≤ 画布宽
L141  更好的做法：不要用绝对定位，用 **flex 竖排**（永远不会重叠）
        ↓
一条要它算，一条说别算 ⇒ 混合信号（用户已指出这条逻辑不对）
```

### ⑧ 「短句 ≤8 字」vs「卖点必须有数字」vs「promo 要超大数字」

```
L448  短句/诗化：单句 ≤ 8 字
L450  卖点式：每句必须有一个数字或一个对比
CONTENTS.promo：超大数字（价格/折扣占短边 40%+）
        ↓
三个方向，选不同组合会互相抵消
```

### ⑨ TRACE 要求「每段都写」但没强制

```
TRACE：「每段」: [{秒, 视觉类型, 为什么, 工具}]
        ↓
实测：12 段的片子只写了 **3 条**
        ↓
⇒ "每段"两个字没有约束力
```

### ⑩ 「自检 ≤5 分先改再输出」vs 「输出只给 HTML」

```
自评：只要有一项 ≤ 5 分，**先改再输出**
输出：只输出一个完整 HTML，不要解释
        ↓
⇒ 它没法"先改再输出"（因为看不到中间过程）⇒ 这条形同虚设
```

## 汇总：为什么它总"贴着下限走"

```
我们的 prompt 里有两类信号：
  A. 硬底线（至少 X / 不许 Y）  ⇒ 必须满足，权重 100
  B. 档位设定（多=5~6 / 少=0~2）⇒ 建议，权重 50
        ↓
它永远优先满足 A，然后**用最低成本达标**
        ↓
⇒ 所有 B 都被 A 吃掉
        ↓
证据：
  · 装饰"多"→ 做 3.5 类（A 的下限）
  · 主体占比 → 60%（40~65% 的中点）
  · brightness → 0.95（刚好的边界）
```
