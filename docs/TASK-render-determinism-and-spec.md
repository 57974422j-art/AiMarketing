## 2. 任务 A：帧确定性自检工具

### 2.1 新文件

```
scripts/video-factory/tools/frame-determinism-check.mjs
```

### 2.2 它做什么

对**同一份 HTML**，用**两种不同的请求顺序**渲染同一批帧，比对像素是否逐字节一致：

```
第一遍：按 [0, 1, 2, 3, 4, 5] 顺序请求
第二遍：按 [4, 1, 5, 0, 3, 2] 乱序请求
         ↓
对每个帧号比对 SHA256（或像素差异比例）
         ↓
输出：全部一致 ✅ / 列出不一致的帧号 + 差异比例 ❌
```

**为什么这个能抓 bug**：如果页面里某处用了 `Math.random()`、`Date.now()`、或"第一次画才初始化"的全局状态，那么乱序请求时同一帧会画出**不同的画面** —— 这正是"渲染结果不可复现"的根源（我们踩过类似的：抖动、字体加载时序）。

### 2.3 同时要报的"顺带体检"

渲染过程中如果拿得到这些信号，一并打出来（拿不到就写"未采集"）：

- 页面 **console error / pageerror**
- **字体加载失败**（`document.fonts` 的 failed 项）
- **音频缺失**（引用了音频但解码失败）
- **文字被裁切**（元素 `scrollWidth > clientWidth` 之类）

### 2.4 用法（CLI）

```bash
node scripts/video-factory/tools/frame-determinism-check.mjs <html路径> [--frames 0,15,30,60] [--out report.json]
```

- 不给 `--frames` ⇒ 默认均匀取 8 帧（含首尾）
- 输出人类可读结论 + 可选 JSON

### 2.5 验证方法（必须真跑）

1. **拿一份现有日报页跑** ⇒ 应该输出"全部一致"（如果这里就不一致，说明我们**现在就有不确定性**，那是重大发现，先记录）；
2. **故意注入不确定性**：复制一份页面，加一行 `document.body.dataset.r = Math.random()` 参与渲染 ⇒ 工具**必须抓出不一致**；
3. 把两次的结论贴进 `EXECUTION_LOG.md`。

### 2.6 明确不做

- ❌ **不接入出片主流程**（先做独立工具，跑稳了再讨论"要不要做成出片前闸门"）
- ❌ 不自动修任何东西
- ❌ 不做像素级 diff 图（只报比例与帧号）

## 3. 任务 B：hyperframes 契约文档

### 3.1 新文件

```
docs/hyperframes-SPEC.md
```

### 3.2 铁律：**每一节都必须对应到真实代码**

写之前**先读**真实实现（至少这几处）：

- `scripts/video-factory/html-deck/node_modules/hyperframes/`（核心）
- `scripts/video-factory/html-deck/tools/render-film.mjs`（HTML成片怎么用它）
- `scripts/video-factory/html-deck/tools/daily-film.mjs`（日报怎么用它）
- 日报页模板 `daily-page.mjs` 里暴露给引擎的钩子

⚠️ **不许凭印象写**。写不出依据的章节，标 `（待确认）` 并说明卡在哪。

### 3.3 必须回答的问题（文档目录建议）

| 章节 | 要写清什么 |
|---|---|
| **1. 页面契约** | 页面要暴露什么（函数名/全局变量/属性）、什么时候算"就绪" |
| **2. 逐帧渲染方式** | 引擎怎么让页面"跳到第 t 秒"（是 seek？是调函数？是设 CSS？）|
| **3. 时间轴来源** | 段/镜头的时间信息从哪读（DOM 的 `data-start`/`data-duration`？还是 JS 数组？） |
| **4. 素材引用规则** | 图片/音频/字体的引用方式（内嵌 vs 同级文件 vs 变量），以及**校验闸门认什么**（这里必须提 `missing_local_asset`） |
| **5. 确定性要求** | 同一个 t 必须永远画出同一张图（为什么：帧是乱序/并行请求的） |
| **6. 已知闸门清单** | 用字闸门 / 引擎校验 / 抖动兜底 各自在哪、检查什么 |
| **7. 常见坑** | 至少写 3 条真实踩过的（例如：内嵌图体积、字体抓取、占位文件名被判缺失） |

### 3.4 验收标准

1. **每节都有代码行号或文件路径支撑**（不能只有结论）；
2. **给一个不了解本项目的人看**：他只看这份文档，能写出一个"能被 hyperframes 正确渲染"的最小页面（把这段写成文档末尾的"最小示例"）；
3. **最小示例必须真跑一次**（用现有渲染工具渲几帧，确认能出画面）。
