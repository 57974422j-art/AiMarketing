# 当前方案与 B 计划（纯 Agent 模式）分析

---

## A 计划（当前方案）：脚本主导 + AI 监控

### 架构
```
Layer 1: 导航栏锚点反推（首页+我 → 反推+号坐标）
Layer 2: Fuzzy XML 文本匹配
Layer 3: 本地缓存坐标表
AI: 每步截图 → 百炼 qwen-vl-max 分析 → 日志反馈（仅监控，不控制）
```

### 现状
- 发布流程基本可跑通，但存在模拟器点击响应问题
- 标题输入通过 ADBKeyBoard 广播绕过键盘
- AI 已在关键页面切换点介入，输出页面分析日志
- 每次发布约 4 次 AI 调用（post_plus / post_pick / after_next / publish）

### 成本
- **百炼 qwen-vl-max**：单次 ~¥0.005，一次发布 ~¥0.02
- **零额外硬件成本**
- **一个人维护即可**，80% 场景不依赖 AI

---

## B 计划（纯 Agent 模式）：AI 完全驱动

### 架构
```
循环 {
  1. 截图
  2. 发给 AI（含目标 + 当前阶段 + 历史上下文）
  3. AI 返回结构化决策 { status, action, coords, text }
  4. 执行命令
  5. 截图验证是否达到预期
  6. 不符合预期 → AI 纠错
}
```

### 优缺点

| 项目 | A 计划 | B 计划 |
|------|--------|--------|
| 自动化程度 | 脚本主控 + AI 辅助 | AI 全权控制流程 |
| 抗 UI 变化 | 中（需调定位参数） | 高（AI 看图识别） |
| 每步耗时 | ~1s（不调 AI）/ ~5s（调 AI） | ~5-8s（每步都要 AI） |
| 一次发布耗时 | ~30-40s | ~2-3 分钟 |
| 维护成本 | 改版约 1 小时 | 几乎零维护 |
| 开发工作量 | 已完成 | 需 1-2 天重构 |

### 成本对比

| 项目 | 单价 | 一次发布 |

### 成本对比总表

| 方式 | 单条成本 | 月 1000 条 | 开发量 | 维护量 |

| A（当前脚本+AI监控） | ~¥0.02 | ~¥20 | 已完 | 改版需1h |
| B1（百炼VL API全程） | ~¥0.15 | ~¥150 | 1-2天 | 几乎0 |
| B2（AutoDL 自建） | ~¥0.07 | ~¥70 | 2-3天 | 几乎0 |
| B3（硅基VL API） | ~¥0.04 | ~¥40 | 1-2天 | 几乎0 |

### 推荐路径

1. **继续 A 计划跑通当前流程** — 标题输入修好后先跑一段时间
2. **同时用硅基流动 VL API 做 B 计划试点** — 不改脚本，只加一个 `aiDecideNext()` 函数，在 `publishVideo` 的每个步骤前插一个 AI 决策点。成本最低（¥0.04/条），开发量适中
3. **稳定后可根据量和延迟决定是否需要 AutoDL** — 如果量大会每日百条以上，AutoDL 自建成本更低
