## 0. 一句话目标与结论

**目标**：让"AI 设计的响应式落地页"能直接出片（竖 720×1280 / 横 1280×720），
而不是让 AI 在没有闸门的情况下自由写整站 HTML。

**已验证的结论（硬事实）**
1. ✅ **"一份设计吃两种画幅"技术上成立**：响应式会**真重排**（竖屏上下 / 横屏左右），不是缩放。
2. ✅ **"设计 → 出片"闭环已打通**：HTML（带 `window.__seek(t)`）→ 逐帧截图 → ffmpeg → MP4（见 §4 测试片）。
3. ❌ **AI 侧（外部模型）目前做不好**：3 件外发样本**全部**过结构闸门、**全部**不过观感闸门
   —— 一致缺陷：**字号偏小**（8.64~11px）、**横屏空 / 文字压图**、**没有可预览的多段结构**（双击只看到一屏）。
4. ✅ **按本规范写的样本可以全绿**：`d-daily`（日报纸感）/ `e-neon`（赛博）在**三档画布**（竖/横/窄窗）
   过 R3~R14 全部判定。

## 2. 判据正本 R1~R14（给 AI 实测时就是拿这套量它）

| 编号 | 判据 | 阈值 |
|---|---|---|
| R1 | 一屏一段（多段见 R11） | 不滚动、无导航页脚 |
| R2 | 双画布成立；只用 grid/flex/%/aspect-ratio/clamp | 禁绝对定位布局块 |
| R3 | 正文/标签 ≥22px；注脚 ≥18px；**竖屏主标题 ≥40px**（横屏 ≥32） | 禁 clamp 下探 |
| R4 | 底部条带内容覆盖率（横 y>60% / 竖 y>80%） | ≥20% |
| R5 | 文字不压图（文字 ∩ 图片 > 较小矩形 15%） | 0 处（除非 ≥60% 不透明底衬） |
| R6 | 对比度（与 `tools/theme.mjs` 同口径） | 正文 4.5 / 次要 3.0 / 强调 2.0 |
| R7 | 素材槽位：`<img src="images/N.jpg">` + object-fit | 有真图不许用渐变假图 |
| R8 | 确定性：无外链 / 无随机 / 无自播动画；`__seek(t)`；t=0 不得空白 | 外链 0 |
| R9 | 段契约 `section.sec[data-seg][data-start][data-duration]` | 属性名一字不差 |
| R10 | 不许编数据 | — |
| **R11** | 文字量上限（标题 ≤12 字 / 副文 ≤28 建议省 / 信息点 ≤3×≤8 字 / 每块 ≤2 行）+ **双模式** | 预览可见段数 = 段总数 |
| **R12** | 出片动效：≥4 类，**必须含文字位移**（只整块淡入不算） | t=0.2 vs 2.0：≥5 元素动 且 ≥1 处文字位移 |
| **R13** | 预览动效：**打开文件时就在动**（不许是静止完成帧） | 不调 __seek，隔 700ms：≥3 元素动 |
| **R14** | 折行：短文本（≤8 字）高度 ≤ 1.6×(行高+上下内边距) | 0 处 |

**三档画布**：竖 720×1280 · 横 1280×720 · **窄窗 520×1000**（只有第 3 档能抓"窗口拖窄 ⇒ 标签折行"）。

## 3. 判据标定史（★给 AI 实测时最有价值：说明"判据必须能证伪"）

| 轮次 | 判据改动 | 实测后果（教训） |
|---|---|---|
| v2 | 文字 ∩ 任何渐变层 = 压图 | **误报 46 处**（文字在页面渐变底上） |
| v2.1 | 整页背景层不算图片 | 剩 4 处（对了）；`<em>` 自带高亮底 ⇒ 误报 1 处 |
| v2.2 | "带文字的元素不算图片" | **漏报**：`figure` 内含 `figcaption` 被放过 ⇒ 真压图消失 |
| v2.3 | 按**直接文本节点**判定 | 三件样本 0/1/4，与肉眼完全一致 ✅ |
| v2.4 | 加**缺图检测** + 主标题字号 | 抓到外发 v2/v3 缺图 14 张、v3 有 4 处 20px 小字 |
| v2.5 | 加 R11（预览段数）+ R12（动效计数） | 量出"打开只看到 1 屏""打开是死的" |
| v2.6 | `opacity` 不继承 ⇒ 改**累乘祖先**；文字动效拆"位移/仅淡入" | 修前把"父级淡入"当成没动（漏判） |
| v2.7 | 加 **R13**（不调 __seek 也测动效） | 直接量到用户那句"我看不到动效" |
| **v2.8** | 可见性也改累乘祖先 | film 态下**段与段叠在一起互判压图**、覆盖率 105% 的假报警 |
| **v2.9** | 加 **R14 折行**；第一版用 `字号×1.7` | **误报**"封面故事 41px/22px"（其实是 22px 字 + 8px 内边距的印章）⇒ 改"行高+内边距"口径 |

**一句话**：这 9 次里有 **5 次是判据自己错**（误报/漏报）——**"看起来通过"不等于"判据跑了"**，
所以每条判据都要能**证伪**（用已知真值的样本回归）。

## 7. 产品落点讨论（2026-10-12 用户提议）

**用户原话**：「不要一次就搞 HTML 成片 AI 自主，我觉得我们应该加一个让我们的 AI AGENT 有做**日报落地页**的能力。」

**我的判断：赞成，而且比"AI 自由写 HTML"更符合我们已经攒下的资产。** 理由：
1. 我们已经有的东西（R1~R14 闸门、双画布重排、双模式预览、逐帧出片、`data-*` 段契约）**正好是"受约束的模板族"需要的**；
   而"AI 自由写整页"会让这些闸门**全部失效**（外发 3 件样本就是证据）；
2. "日报落地页"= **一个风格族**（L0 皮肤 + L1 构图语法 + L2 动效语法 + L3 文本形态），
   本质是**风格包**（我们已有全套机制），不是"AI 自由创作"；
3. 分期落点（建议）：
   - **阶段 1（现在）**：把 `d-daily` 固化成**参数化模板族**（段数/文案字数/图数/动效档 + 字体字号规范）；
   - **阶段 2**：AGENT 页加一条线（入口词 + 卡片 + 选素材 + 出片），复用现有成片线的骨架；
   - **阶段 3**：让 AI 在**受约束范围**内排段落（B 路线"分段表"，我们的闸门验它）；
   - **阶段 4**：才考虑放开"AI 写段内 HTML"（C2：只写一段、只换坏段）。
4. 建议**不只做"日报"一族**：日报/杂志（`d-daily`）+ 赛博 HUD（`e-neon`）+ 暖食/电商实拍，
   共 **3~5 个"落地页族"**，每个族都带自己的 R1~R14 参数与样例片 —— 用户按行业挑族，AI 只填内容。
