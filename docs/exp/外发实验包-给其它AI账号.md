# 外发实验包（给其它 AI 账号 / 其它 IDE 用）

> 用途：让**别的账号**（有免费额度、环境不同）帮我们生成"成片页面 HTML"，做完带回本仓库审核。
> 本轮只做**实验**：不改造现有引擎、不追求能直接出片，只验证「响应式 + 确定性」这条路走不走得通。
> 带回方式见文末「交付与回收」。

---

## 0. 全部实验共用的硬约束（每一份提示词里都要带上，不能省）

```
【任务】为一个「视频成片页面」写一个**单文件 HTML**（CSS/JS 内联，不用构建工具、不用框架）。
【画布】同一份页面必须同时适配两个固定画布：竖屏 720×1280 与 横屏 1280×720。
【硬约束，逐条必须满足】
1) 响应式：布局只用 grid / flex / 百分比 / aspect-ratio / clamp() / min() / max()。
   禁止用 position:absolute + left/top 像素来定位布局块（装饰性绝对定位也不建议）。
   字号允许 clamp()；圆角/边框/阴影可以用 px。
2) 确定性（要逐帧渲染成视频，所以必须"同一时刻=同一画面"）：
   - 禁止一切网络请求（无外链字体、无 CDN、无 fetch）
   - 禁止 Math.random() / Date.now() / 定时器驱动的自动动画
   - 动画统一走时间轴接口：实现 window.__seek(t)（t=秒，浮点），内部把 t 写进 CSS 变量（例如 --t），
     所有视觉变化都由 --t 的 CSS 计算决定。页面加载后**静止在 t=0 的画面**（不要自动播放）。
3) 中文文案：写 3~5 条**真实感**文案（不要 Lorem、不要"示例文本"），并处理"超长不溢出"（line-clamp 或字号自适应）。
4) 图片：**用 CSS 渐变占位**（不要引用不存在的文件、不要外链图片）。
   在 HTML 顶部注释里列出"图片槽位"：每张图的用途 + 建议比例（如 主视觉 3:4 / 小图 1:1）。
5) 全中文界面文字；除中文字体外不声明任何 @font-face。
【自检】交付时附一段说明：逐条回答上面 5 条你怎么满足的，并写明你在哪个画幅下**没把握**的地方。
【交付】单个 .html 文件 + 一段说明文字。不要压缩包、不要多文件依赖。
```

## 实验 B｜先出分段表，再写页面（AI 编排方向）

```
（先粘贴上面的【0. 共用硬约束】）

【素材】17 张实拍（文件名：20261011_001.jpg ~ 20261011_019.jpg 中取 17 张）
【题材】京味铜锅涮肉（美食）+ 门店环境
【本实验额外要求】两步走：

第 1 步：先输出一份「分段表」JSON（8~16 段），每段包含：
  seg 序号 / 用哪几张素材文件名（1~6 张）/ 结构类型（从下选：opening-hero、works-wall、glass-product、
  data-dashboard、fullbleed、plate-top、plate-bottom、grid-2x2）/ 是否满屏压字 / 文字动效意图（推入/擦除/叠化）
  / 该段一句话主题 / 时长估计（秒）。
  要求：**首段是封面、末段是结尾**；同一张图不要在同一段出现两次；README 里说明"为什么这样排"。

第 2 步：只挑**其中 2 段**（1 段多图拼贴 + 1 段满屏压字）写出对应的单文件 HTML（遵守共用硬约束）。

输出：分段表 JSON + 2 个 HTML 全文 + 一段说明（你的排布逻辑、以及你自认最容易翻车的一段）。
```

## 实验 C｜压力测试（专挑最容易崩的情况）

```
（先粘贴上面的【0. 共用硬约束】）

【本实验额外要求】写 3 个单文件 HTML，每个专打一种"极端情况"，用来测试我们的闸门：
  C1 超长中文：标题 24 个汉字、副文 60 个汉字，不许溢出、不许缩成读不清的小字（最小字号不低于 22px）。
  C2 拥挤：1 张主视觉 + 6 张小图同屏（6 张小图要有主次，不许糊成一团）。
  C3 无图纯字：没有任何图片槽位，只有标题 + 3 条信息点 + 一条进度感装饰，且要**不空**（不能大片死白/死黑）。

每个都必须在**竖屏 720×1280 与横屏 1280×720 双画幅**下都成立。
输出：3 个 HTML 全文 + 每个一段"我认为最可能崩的点"。
```
