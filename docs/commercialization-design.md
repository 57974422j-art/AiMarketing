## 一、用户登录引导路径

### 1.1 当前问题

原方案让用户一注册就选媒体→登记账号→申请设备→选行业——**用户还不知道自己要什么服务，无法做出合理决策**。

### 1.2 推荐引导流程

```
注册/登录
   ↓
【快速画像】(30秒完成，3个问题)
   ↓
  Q1: 您的主要业务场景？
      [电商带货] [本地生活引流] [品牌推广] [内容创作] [其他]
   ↓
  Q2: 您目前有几个运营账号？
      [1-3个] [4-10个] [10-50个] [50个以上]
   ↓
  Q3: 您希望 AI 帮您做什么？（多选）
      ☐ 自动回复私信/评论    ☐ 自动写文案/脚本
      ☐ 竞品数据监控         ☐ 直播场控/数字人主播
      ☐ 批量互动(点赞/关注)  ☐ 线索自动录入

   ↓ 系统根据画像智能推荐方案 ──→
   ↓
┌──────────────────────────────────────────────────┐
│                个性化推荐页                        │
│                                                   │
│  基于您的画像，我们推荐：                           │
│                                                   │
│  ┌─────────────┐  ┌─────────────┐  ┌───────────┐ │
│  │ 🎯 推荐套餐   │  │ 💡 单项服务   │  │ 🔧 设备配置 │ │
│  │             │  │             │  │           │ │
│  │ 入门版 ¥99/  │  │ ☑ AI客服 ¥49│  │ 指纹浏览器  │ │
│  │ 月          │  │ ☑ AI文案 ¥39│  │ (已包含)   │ │
│  │ 含3个账号    │  │ □ 数据监控 ¥29│  │           │ │
│  │             │  │ □ 直播助手 ¥129│ │ 需更多账号? │ │
│  │ [立即订阅]   │  │             │  │ [升级设备]  │ │
│  └─────────────┘  └─────────────┘  └───────────┘ │
│                                                   │
│  后续步骤：                                       │
│  → 绑定您的媒体账号（支持多平台）                    │
│  → 选择行业标签（用于 AI 回复风格优化）              │
│  → 配置设备（指纹浏览器 / 真机接入 / Q1 设备池）     │
└──────────────────────────────────────────────────┘
```

### 1.3 引导路径改动理由

| 原方案 | 改进 |
|--------|------|
| 一上来就选媒体平台 | 先问场景，系统智能推荐 |
| 设备选择放在服务之前 | 设备跟服务绑定，先选服务再配设备 |
| 行业放最后 | 行业影响 AI 风格和数据维度，应前置 |
| 用户自主决策全部选项 | 用画像驱动推荐 + 可自选，降低决策疲劳 |

## 二、定价体系总览（四层模型）

```
┌─────────────────────────────────────────────────────┐
│                   定价体系架构                         │
├─────────────────────────────────────────────────────┤
│                                                     │
│  Layer 1: 基础订阅（平台使用费）                      │
│  ─────────────────────────                          │
│  决定：账号数量 + 基础功能范围 + 设备类型               │
│                                                     │
│  Layer 2: 服务模块（功能费）— 可叠加                  │
│  ───────────────────────────────                     │
│  决定：具体用哪些 AI/自动化能力                       │
│  每个模块支持「包月」或「按量付费」二选一               │
│                                                     │
│  Layer 3: 消耗型资源（用量费）— 按需                  │
│  ─────────────────────────────                       │
│  决定：AI 调用次数 / 数据采集量 / 设备时长             │
│                                                     │
│  Layer 4: 代理商专属套餐                             │
│  ─────────────────────                               │
│  决定：Q1 设备池 / 子账户管理 / API 开放 / 抽成       │
│                                                     │
└─────────────────────────────────────────────────────┘
```

## 三、Layer 1: 基础订阅套餐

### 3.1 终端客户套餐（三档）

| | 免费版 | 专业版 | 企业版 |
|--|--------|--------|--------|
| **价格** | **¥0** | **¥199/月** | **¥599/月** |
| **账号数** | 1 个 | 5 个 | 20 个 |
| **媒体平台** | 单平台 | 3 平台 | 全平台（抖音+小红书+快手+视频号+B站） |
| **基础数据看板** | ✅ 近7天 | ✅ 近90天 | ✅ 近365天 + 自定义报表 |
| **设备类型** | 仅指纹浏览器 | 浏览器 + 真机接入 | 全部含 Q1 设备池使用权 |
| **子账户/团队** | - | - | 5 个成员角色权限 |
| **AI 客服** | - | 1 个智能体 | 5 个智能体 |
| **数据存储** | 7 天自动清理 | 90 天 | 永久保存 |
| **技术支持** | 社区 | 工单(48h) | 专属群(4h) |

### 3.2 适用对象

- **免费版**：体验用户、个人博主试用（获客漏斗入口）
- **专业版**：小商家、个体户、1-5人运营团队（主推款）
- **企业版**：MCN机构、代运营团队、中型电商

## 六、Layer 4: 代理商专属套餐

### 6.1 经销商版 vs 运营中心版

| | **经销商版** | **运营中心版** |
|--|-------------|---------------|
| **价格** | **¥1,999/月** | **¥4,999/月起** |
| **管理端子账户** | 10 个 | 不限 |
| **下属客户数** | 最高 50 家 | 不限 |
| **Q1 设备池** | 10 台使用权 | 50 台起（可扩容） |
| **每客户分配账号** | 各最高 5 个 | 不限 |
| **白标定制** | Logo + 品牌色替换 | 完全白标 + 自定义域名 + 登录页 |
| **API 开放度** | 只读 API（拉取数据） | 全开放 API + Webhook 回调 |
| **定价自主权** | 在建议价 ±20% 内调整 | 完全自定义定价 + 抽成模式 |
| **数据看板** | 汇总看板（所有客户聚合） | 完整 BI + 自定义报表 + 导出 |
| **技术支持** | 工单优先通道 | 专属客户经理 + 远程协助 |
| **培训赋能** | 产品手册 + 视频教程 | 线上培训 + 线下工作坊 |

### 6.2 代理商业务模式

```
模式A: 差价模式（经销商常用）
  进货成本: 向平台支付经销商版订阅费
  收入来源: 将各模块加价后卖给终端客户
  例: AI客服 进价¥69 → 卖给客户 ¥99 (利润¥30/月/客户)

模式B: 抽成模式（运营中心常用）
  平台授权: 运营中心版提供完整 SaaS 能力
  收入来源: 按客户消费额抽取佣金 (10%-30% 可议)
  例: 客户当月消费¥2000 → 运营中心抽成 ¥200-600

模式C: 项目制（代运营）
  项目打包: 套餐 + 代运营服务费
  例: "抖音代运营套餐 ¥5000/月" 含:
    - 企业版账号 × 3
    - AI客服 + 直播场控 + 数据监控
    - 代运营人工服务
```

## 八、风险控制与合规

| 风险点 | 说明 | 应对措施 |
|--------|------|---------|
| **定价复杂度高** | 四层模型可能让用户困惑 | 前端用画像推荐卡片简化呈现；后端灵活分层 |
| **按量不可预期** | 用户担心超支 | **硬上限 + 到额确认**，绝不允许静默扣费 |
| **代理商低价倾销** | 经销商可能破坏价格体系 | 设最低售价限制；超低价触发审计 |
| **平台合规风险** | 自动回复/批量互动可能违反平台规则 | 每功能入口加风控提示；默认保守日上限 |
| **免费版滥用** | 可能被羊毛党利用 | 单账号限制 + 手机验证 + IP 频率限制 |
| **冷启动转化低** | 用户不愿为未体验的功能付费 | 免费版必须有完整 Aha moment（至少1账号+基础功能可用） |

## 九、与现有系统的集成要点

### 9.1 需新增的数据模型

```prisma
// 订阅计划定义
model SubscriptionPlan {
  id          Int      @id @default(autoincrement())
  name        String                          // "免费版/专业版/企业版"
  tier        String   // "free/professional/enterprise"
  price       Decimal  @db.Decimal(10, 2)
  monthLimit  Int?                            // 各项资源上限(JSON)
  isActive    Boolean  @default(true)
}

// 用户订阅记录
model UserSubscription {
  id          Int      @id @default(autoincrement())
  userId      Int
  planId      Int
  status      String   // "active/cancelled/expired"
  startedAt   DateTime @default(now())
  expiresAt   DateTime
  paymentMethod String?                     // "alipay/wechat/manual"

  user        User            @relation(...)
  plan        SubscriptionPlan @relation(...)
  moduleActivations ModuleActivation[]
}

// 模块激活记录（用户开通了哪些模块）
model ModuleActivation {
  id            Int      @id @default(autoincrement())
  subscriptionId Int
  moduleId      String   // "M1~M8"
  billingMode   String   // "subscription/usage"  // 包月 or 按量
  status        String   // "active/paused"
  quotaUsed     Int      @default(0)             // 已用量
  quotaLimit    Int?                              // 上限(null=无限制)
}

// 使用量明细
model UsageRecord {
  id          Int      @id @default(autoincrement())
  userId      Int
  moduleId    String
  action      String   // "chat/tts/video/digital-human/..."
  quantity    Decimal  @db.Decimal(10, 2)        // 消耗数量
  unitCost    Decimal  @db.Decimal(10, 2)        // 单价
  totalCost   Decimal  @db.Decimal(10, 2)        // 小计
  createdAt   DateTime @default(now())
}
```

### 9.2 配额中间件设计

```
每次 API 调用时:
  
  请求进入
     ↓
  [Quota Middleware] 
     ↓ 查询 UserSubscription + ModuleActivation
     ↓
  ┌─ 有活跃订阅且未超限额？ ──→ ✅ 放行 → 执行业务逻辑
  │
  └─ 超额或无订阅？ ──→ 
       ├─ 免费版用户且在免费额度内 → ✅ 放行 + 标记
       └─ 真的超额 → ❌ 返回 402 + 提示升级
       
  响应返回
     ↓
  [异步] 写入 UsageRecord (不计入主流程耗时)
```
