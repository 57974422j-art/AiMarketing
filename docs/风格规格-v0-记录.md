# 风格规格 v0 · 记录（2026-10-10）

> 起因（用户问）：**怎么才能让 AI 知道怎么做 —— 一个命令下去，说什么风格它就能做出来？这个模板/提示词怎么写？**
> 本文件是**记录与设计规划**，不含任何产品代码改动。实验产物在 `temp/_travfilm/`（临时目录）。

---

## 一、结论先说：不是"提示词写得花"，是**把风格拆成能填的规格**

实验证据（同一批 17 张旅游素材，同一套内容/构图脚本，**只换一份规格文件**）：

| 风格 | 规格 id | 实测结果 |
|---|---|---|
| 宣纸册页（样例 1） | `zhishi` | 字表 ✓ / 21-21 对比度 ✓ / 出片 53.5s |
| 夜色霓虹 | `neon` | 同上 ✓（一次生成即过闸门） |
| 极简瑞士网格 | `swiss` | 同上 ✓ |
| 复古胶片 | `retro` | 同上 ✓ |

⇒ **风格 = 「tokens + 版式语法 + 动效语法」三组字段**；内容脚本固定，规格一换、风格就变。
⇒ AI 要填的**只有这份 JSON**（字段少、有边界、可校验）；HTML/动效由生成器或 AI 按规格写。

## 二、风格规格 v0（字段表 = 让 AI 填空的东西）

| 组 | 字段 | 含义 / 取值 |
|---|---|---|
| 色彩 | `paper` `ink` `muted` `accent` | 底 / 主字 / 次字 / 点缀。**只用 3~4 色**（颜色稀缺是"高级感"的来源） |
| 字体 | `font` | `serif`（衬线，人文/古典）｜`sans`（无衬线，现代/电商） |
| 版式 | `titleMode` `titleSize` `tracking` | 标题竖排/横排、字号、字距 |
| 版式 | `frame` `bgFx` `header` | 内嵌细框 / 背景纹样（`noise`纸纹 `grid`网格 `glow`辉光 `grain`颗粒）/ 页眉字 |
| 照片 | `photo.mat` `padTop` `padBottom` `radius` `shadow` `border` `tag` | 相纸底色、留白、圆角、投影、边框、是否带说明小字 |
| 点缀 | `rule` | 细线颜色（`accent`/`ink`/`none`） |
| 动效 | `motion.reveal` | `wipe`（上下擦入）｜`rise`（上浮）｜`blur`（虚化聚焦） |
| 动效 | `motion.float` `stamp` `crossfade` | 落位后浮动幅度 / 印章落下 / 段间交叉淡出秒数 |

（另有构图脚本：`pages[] = { kind, images[], title, tag, note }`，10 页 / 17 张图 / **全部完整呈现**。）

## 三、提示词模板（给 AI 的"一页纸"，配 skill 用）

```
【角色】你是竖屏短视频（9:16 · 720×1280）的视觉导演，不是文案机。

【输入】
① 素材清单：每张一句真实描述（用视觉模型读图得到，不许自己想象）
② 总时长：45~60 秒
③ 风格规格：可留空（= 你按素材气质自己定）；不为空时按它执行

【输出】只回一个 JSON（不要解释、不要 markdown 围栏）：
{ "spec": { …风格规格 v0 的字段… },
  "pages": [ { "kind":"open|single|double|stack|grid4|triple|end",
               "images":["p03","p06"], "title":"…", "tag":"…", "note":"…" } ] }

【硬规矩（违反即返工）】
1. 只能用给定素材；**不许**编造数据、品牌、门店、人物身份
2. 每页在屏文字 ≤ 60 字；标题 ≤ 6 字；说明 ≤ 20 字
3. **照片必须完整**（不许裁切铺满）；一页最多 4 张
4. 用字必须在引擎字体子集内（避开生僻字；本引擎已有"字表闸门"会拦）
5. 不许 emoji、不许英文口号堆砌（除页眉这类可读的短标记）
6. **颜色稀缺**：整片点缀色只出现在细线/页码/印章这类小面积

【自检（出片前你逐条过）】
□ 是否每张图都完整？ □ 每页字数达标？ □ 点缀色有没有泛滥？
□ 节奏是否有起伏（快慢各一处）？ □ 结尾是否回扣开头？
```

**命令示例**（用户侧只这一句）：
> 「用**夜色霓虹**风格，把这 17 张做成 50 秒的片」

服务端流程：`规格 → 生成 HTML → 字表闸门 → 引擎 check（对比度/重叠/溢出）→ 逐帧渲染 → 出片 → 你看片给品味分 → 打分写回"参考语料"`。

## 五、机器闸门（这次实测，AI 自己画也会被抓）

| 闸门 | 这次抓到了什么 | 处理 |
|---|---|---|
| 字表闸门（`check-page-fonts.mjs`） | 我写的 **匾 / 黛 / 檐** 三个表外字 | 改成 题名 / 黑瓦 / 廊下 ⇒ `205 个非 ASCII 字符全部在表内` |
| 引擎 check（对比度/重叠/溢出） | **8 处文字对比度不足**（灰字 3.5~4.3:1，未达 4.5:1） | 灰字加深 `#6E675C→#5C5446` ⇒ `21/21 text checks pass WCAG AA` |

⇒ **"AI 自由画"可行，前提是"生成 + 机器验收 + 修复"闭环**（否则就是豆腐块 + 看不见的灰字）。

## 八、怎么在项目里**教会 AI 做风格**（设计；本节只记录，未实施）

### 8.1 三层，缺一不可

| 层 | 是什么 | 现有资产 | 缺什么 |
|---|---|---|---|
| ① **规格** | AI 唯一产出：一份 JSON 字段表 | `styles/*.json`（11 套，**只覆盖 L0 皮肤**）；`temp/_travfilm/_styles.json`（v0：L0 + 一点 L1/L2）；**语法实验（同色三条）已验证 L1/L2/L3 可换** | 把 v1 字段**定稿并让渲染器真正支持**（字段表见 `docs/风格语法-实验记录.md` §二/§⑧/§⑩） |
| ② **提示词 / skill** | 一页纸：角色 · 输入 · 输出 schema · 硬规矩 · 自检 | 成片线 `capabilityBrief()`；本文档 §三 的模板 | 把"**档位选择 + 规格字段说明 + 自检清单**"合成一份**可版本化**的 skill（命令一句话触发） |
| ③ **闸门 + 品味反馈** | 机器验收 + 你采纳/淘汰 | 字表闸门 / 引擎 check（对比度·重叠·溢出）/ 完整大图配额 / 排版纪律（页型·图数·转场）/ 空文件闸门 | **品味分回灌**（采纳 → 写参考语料 / 固化成规格或页面）——没有这条，AI 只会"每次重新猜" |

### 8.2 自由度三档（问题从来不是"能不能"，而是"在哪一档、花多少、失败怎么兜"）

| 档 | 谁决定版式 | 变化度 | 成本（对标"AI 直接生成视频"） | 稳定性 | 现状 |
|---|---|---|---|---|---|
| **A 库内重组** | 结构库 + `arrange` | 低 —— **这正是"每条片 90% 像"的原因** | 极低（token + TTS + CPU 渲染） | 最高（逐帧可复现） | ✅ 已在产品里 |
| **B 规格驱动** | AI 出 `spec`（L0~L3），**固定渲染器**解释执行 | 中~高 | 低（多一次 spec 生成） | 高（渲染器固定 ⇒ 可复现、可回归） | 🔶 v0 实验已证明"4 份规格一次过闸门"；渲染器**还没真正支持 L1/L2/L3** |
| **C AI 直接产 HTML/CSS** | AI 全权 | 最高（能长出新页型、新风格） | 中（token 级；**仍远低于视频按秒计费**） | 中（靠闸门 + 失败即丢 + 采纳后固化） | 🔶 实验过 4 风格；未产品化 |

**关键设计（把"花钱"变"攒库"）**：B/C 的产物**一经采纳就固化** ——
规格存进风格库（`styles/` 或运行时库）、页面存进"候选页型库"。
⇒ 下次同风格**直接复用**（不花钱、更稳），库越用越厚 ⇒ 变化度与省钱的矛盾自然消解。

### 8.3 成本口径（**按用户判据：比 AI 直接生成视频省即可**；具体单价请按你们实际服务核）

| 项 | AI 直接生成视频 | 我们这条线（A/B/C 任一档都一样） |
|---|---|---|
| 主成本 | **按秒/按条**生成视频；失败要重生成 = **重复付费** | **CPU 逐帧渲染**（本机/服务器，边际≈电费）+ **token**（文案或规格，一次性）+ **TTS**（按字数）+ **读图**（每张约 0.2 点） |
| 可复现 | 不可（同 prompt 两次不同） | **可**（HTML 固定 ⇒ 逐帧确定） |
| 失败代价 | 重新生成整段（秒级计费） | 不过闸门 ⇒ 只重写规格/页面（token 级），**画面不重渲** |
| 结论 | — | **即使走 C 档，成本结构仍是"token 级"，比"AI 生成视频"低一个量级**（倍数按实际单价乘） |

### 8.4 验收判据（"这次是真换了样式，不是换皮肤"）

1. **同色不同语法对照**（§六 的 A/B/C：满幅电影感 / 拼贴手作 / 极简纸面）：
   tokens 几乎不动、**只换 L1/L2** ⇒ 如果三条"看不出是同一套"，就说明 B 档成立。
2. **可复现判据**：同一份 spec 渲两次 ⇒ 产物逐帧一致（否则"可验收"就没了）。
3. **成本判据**：一条片的 token 成本 × 单价 < "AI 生成视频"同长度成本 ⇒ 继续。
4. **批量判据**（每天发多条时）：同批 N 条之间也要过闸门（版式序列不同 / 风格不同 / 句型不重复）。

### 8.5 建议路线（等定案再动手）

1. **先定完 L1/L2/L3 字段**（现成草案：`docs/风格语法-实验记录.md` §⑧/§⑩）—— 这是"换风格真换样式"的地基；
2. **B 档当主力**（固定渲染器解释规格）+ **A 档兜底**（B 失败/超时回退）+ **C 档当开关**（"我要新页型/新风格"时用一次）；
3. **采纳即固化 + 品味回灌**；
4. 用 §8.4 的"同色不同语法三条对照"验收 B 档。

### 8.6 现成证据（**这不是设想，已经做过**）——见 `docs/风格语法-实验记录.md`

| 实验 | 做了什么 | 结论 |
|---|---|---|
| 实验 1（v0） | 只换 L0（tokens/palette）出 4 个风格 | **失败**：用户一眼看穿"换了颜色、样式一模一样" ⇒ 证明**只换皮肤不算换风格** |
| **实验 2（v1 语法）** | **tokens 完全相同**，只换 L1 构图 / L2 动效 / L3 文本形态（cinematic 满幅 / collage 拼贴 / quiet 极简） | **成立**：三条**肉眼就是三套**；且**同一套闸门对三种语法都有效**（字表 ✓ / WCAG AA ✓ / 重叠溢出不拦、说明构图自由度有空间） |

⇒ 所以"**AI 能不能自己画、能不能画出不一样的样式**"——**已经验证：能**。
剩下的不是技术可行性，是**产品化取舍**（选哪一档、边界怎么定、采纳怎么固化）。

**实验 2 自查出的 10 个问题**（都带修法，值得直接并入规格）：
换页"闪白"、入场先出空白相纸、**节奏完全均匀**、裁切过狠（竖条裁掉约 78% 宽）、长叠化吃时间发灰、
图偏小（占宽 40%）、小字看不清（12px 且随图旋转）、**文案与素材贴合弱**（标题是人肉拍的抽象词）、
无音频、尾页处理弱。

**要你拍板的 4 件事**（`风格语法-实验记录.md` §⑦ 原文）：
1. **"图片完整" vs "满幅电影感"天然冲突**（满幅必裁）⇒ 是否改成**按风格声明**："此风格固定裁切 / 此风格保证完整"？
2. 拼贴类密度高 ⇒ 是否设"**单图最短可见时长**"（如 ≥2.5s）？
3. 极简类图偏小 ⇒ 是否设"**最小图宽**"（如 ≥320px）？
4. **允许 AI 发明新页型吗**？建议：**允许生成，入库需你点头**（候选 → 正式）。

**两处都撤，且第二处（论据）有实测反证：**

1. 「不许自己画」= 我在 A 档上的取舍，**不是记录口径、也不是用户要求** —— 见本档 §五 与 §8.2（B/C 都在表里，C 已实验过）。
2. 「闸门只对已知结构有效」= **与实测相反**。**闸门校验的是渲染结果，与 HTML 出自谁手无关**：
   - 字表闸门抓出**我手写页面**里的表外字「檐」（**两次**，见 `风格语法-实验记录.md` §4.2②）；

   - **三条语法（都不是库里那 6 种结构）全部过闸门**，且"故意叠压"没被拦（说明构图自由度有空间）。
   ⇒ 所以「AI 画 ⇒ 必然出坏片」不成立；真实代价是**返工（页面不过闸门要重写）**，
   用「生成 + 机器验收 + 修复」闭环压住即可（§五原文就是这个口径）。
