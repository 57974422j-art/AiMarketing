## 1. 功能概述

数据中心是 AiMarketing 平台的核心数据聚合与运营分析模块，提供**采集 → 存储 → 分析 → 转化**的全链路能力。

### 1.1 核心子页面

| 页面 | 路径 | 功能定位 |
|------|------|---------|
| **仪表盘** | `/data-center` | 总览指标、快捷操作入口 |
| **视频库** | `/data-center/videos` | 浏览和管理已采集的视频 |
| **评论池** | `/data-center/comments` | 查看视频关联的评论数据 |
| **线索看板** | `/data-center/leads` | 高意向潜在客户管理与跟进 |
| **用户画像库** | `/data-center/users` | 社交媒体用户档案 |
| **热榜追踪** | `/data-center/trending` | 各平台热门话题追踪 |

### 1.2 支持的数据平台

| 平台 | 标识符 | 视频采集 | 评论采集 | 用户画像 | 热搜榜单 |
|------|--------|:-------:|:-------:|:--------:|:--------:|
| 抖音 | `douyin` | ✅ | ✅ | ✅ | ✅ |
| 小红书 | `xiaohongshu` | ✅ | ✅ | ✅ | — |
| B站 | `bilibili` | ✅ | ✅ | ✅ | — |
| 快手 | `kuaishou` | ✅ | ✅ | — | — |
| 微博 | `weibo` | — | — | — | ✅ |

## 2. 前置条件

### 2.1 MediaCrawler 服务配置

数据采集依赖外部 **MediaCrawler** Python 爬虫服务。使用前需在**管理中心 → 设置**中完成以下配置：

1. **安装部署**: 确保 MediaCrawler 服务已部署并可访问
2. **Cookie 登录**: 通过扫码登录获取目标平台的 Cookie（抖音/小红书等）
3. **Cookie 有效期**: 通常 3-7 天，过期后需重新扫码
4. **连接验证**: 系统会检测 MediaCrawler 服务是否可用

> ⚠️ **注意**: 如果未配置 MediaCrawler 或 Cookie 已过期，采集任务将无法执行，但已采集的历史数据仍可正常浏览。

### 2.2 权限要求

- 所有三层用户（admin / editor / end-user）均可访问数据中心页面
- **创建采集任务**需要有效的用户会话（已登录状态）
- **筛选方案**支持个人方案和共享方案两种模式

页面顶部展示六个核心 KPI 卡片，实时反映数据中心的整体状况：

横向柱状图展示各平台已采集视频的数量分布，帮助快速了解哪个平台的数据最丰富。

### 3.3 线索状态分布

以**标签云**形式展示线索的五态分布：

| 状态 | 颜色 | 含义 |
|------|------|------|
| `new` | 蓝色 | 新发现的潜在客户 |
| `contacted` | 黄色 | 已进行首次联系 |
| `qualified` | 绿色 | 意向已确认 |

### 3.4 近 7 天趋势图

柱状图展示最近 7 天每日新增线索数量趋势，用于评估采集和转化效率的变化。

### 3.5 热门视频 Top5

按点赞数排序展示前 5 个热门视频，包含：
- 封面缩略图

- 平台标签
- 点赞 / 评论 / 分享 / 收藏 数量
- 采集时间

### 3.6 最近采集任务表

显示最近 10 条采集任务的执行情况：

| 字段 | 说明 |
|------|------|
| 任务 ID | 系统生成的唯一标识 |
| 任务名称 | 创建时自定义的名称 |
| 目标平台 | 抖音/小红书/B站等 |
| 任务状态 | pending(待执行) / running(运行中) / completed(成功) / failed(失败) |
| 采集视频数 | 本次采集到的视频数量 |
| 产生线索数 | 从评论中提取到的线索数量 |

当有 **running** 状态的任务时，页面顶部会显示**脉冲动画提示**，且仪表盘每 **5 秒自动刷新**一次数据。

## 4. 视频库

**路径**: `/data-center/videos`

### 4.1 视图模式

支持两种浏览模式，可随时切换：

#### Grid 网格视图（默认）
- 4 列网格布局
- 每个卡片展示：封面缩略图、标题、作者、平台标签、互动数据、采集时间
- 点击封面可查看大图
- 点击标题区域可跳转到评论列表

#### List 列表视图
- 表格详细列表形式
- 列：封面(小)、标题、作者、平台、点赞、评论、分享、收藏、播放量、采集时间
- 信息密度更高，适合批量浏览

### 4.2 搜索与筛选

| 筛选项 | 说明 |
|--------|------|
| **关键词搜索** | 搜索视频标题，支持模糊匹配 |
| **平台筛选** | 下拉选择：全部 / 抖音 / 小红书 / B站 / 快手 / 微博 |
| **排序方式** | 采集时间↓ / 点赞数↓ / 评论数↓ / 播放量↓ |

### 4.3 分页控制

- 默认每页 **20 条**
- 可选：10 / 20 / 50 / 100 条每页
- 支持页码跳转

### 4.4 评论联动

每个视频卡片/行都有**查看评论**按钮，点击后：
- 跳转到 `/data-center/comments?videoId=xxx`
- 自动过滤出该视频的所有评论
- 方便从内容到互动数据的深度钻取

## 5. 评论池

**路径**: `/data-center/comments`

### 5.1 主要功能

浏览已采集的社交媒体评论数据，支持从视频库跳转或独立浏览。

### 5.2 搜索与筛选

| 筛选项 | 说明 |
|--------|------|
| **关键词搜索** | 搜索评论文本内容 |
| **仅含线索** | 复选框，只显示已提取到联系方式的评论 |
| **来源视频** | 从 URL 参数 `?videoId=xx` 自动过滤，也可手动选择 |
| **排序方式** | 采集时间↓ / 点赞数↓ / 意向度↓ / 评论时间↓ |

### 5.3 意向度标识系统

系统通过 AI 分析每条评论的用户购买/咨询意向，用颜色直观区分：

| 意向度范围 | 颜色 | 含义 | 行动建议 |
|-----------|------|------|---------|
| ≥ 0.7 | 🟢 绿色 | 高意向 | 优先跟进，直接联系 |
| ≥ 0.4 | 🟡 黄色 | 中意向 | 关注观察，适时介入 |
| < 0.4 | ⚪ 灰色 | 低/无意向 | 暂不处理，持续监测 |

### 5.4 线索标记

含有提取到联系方式（手机号/微信号）的评论会显示：
- 左侧**绿色边框**
- **"已提取线索 #ID"** 徽章
- 显示提取到的具体联系方式

### 5.5 关键词高亮

当使用关键词搜索时，匹配的文字会在评论文本中以**黄色背景**高亮显示。

## 6. 线索看板

**路径**: `/data-center/leads`

### 6.1 功能定位

线索看板是从评论中自动识别出的**高意向潜在客户**的管理中心。它是数据采集 → 业务转化的关键桥梁。

### 6.2 五态漏斗模型

线索生命周期遵循标准销售漏斗：

```
new(新发现) → contacted(已联系) → qualified(已确认) → converted(已转化)
                                                              ↘ lost(已流失)
```

页面顶部的漏斗概览区展示各状态的数量统计，**点击任意状态可快速筛选**该状态的线索。

### 6.3 多维筛选器

| 维度 | 选项 | 说明 |
|------|------|------|
| **线索状态** | new / contacted / qualified / converted / lost / 全部 | 必选其一 |
| **来源平台** | 抖音 / 小红书 / B站 / 快手 / 微博 / 全部 | 按平台筛选 |
| **关键词** | 文本输入 | 搜索原始评论内容 |
| **最低意向度** | 0.1 ~ 1.0 | 只显示高于该阈值的线索 |
| **排序方式** | 意向度↓ / 更新时间↓ / 采集时间↓ | 结果排序 |

### 6.4 线索卡片信息

每条线索卡片展示：

| 字段 | 来源 |
|------|------|
| **状态徽章** | 颜色编码的状态标签 |
| **平台标签** | 抖音/小红书/B站等 |
| **来源类型** | comment(来自评论) / profile(来自用户简介) |
| **原始内容摘要** | 截断显示的原始评论文本 |
| **意向度分数** | 颜色编码的数值 (0~1) |
| **联系方式** | 提取到的手机号 / 微信号 |
| **标签** | 自动打上的分类标签 |
| **来源任务名** | 是哪次采集任务产生的这条线索 |

### 6.5 状态流转操作

在卡片上可直接变更线索状态（后续版本将完善此交互），建议的流转规则：

1. **new → contacted**: 已经通过电话/微信等方式触达该用户
2. **contacted → qualified**: 用户表达明确的兴趣或需求
3. **qualified → converted**: 完成交易/签约/付费
4. **任何态 → lost**: 用户明确拒绝或长时间无响应（建议设定期限如 30 天）

## 9. 快捷采集面板

**位置**: 仪表盘页面内嵌（展开/收起式）

### 9.1 功能概述

快捷采集是**一键发起数据采集任务**的功能，无需离开仪表盘即可完成从创建到执行的全流程。

### 9.2 操作步骤

1. **打开面板**: 在仪表盘页面点击"快捷采集"按钮展开面板
2. **填写任务信息**:
   - **任务名称**（必填）：给本次采集起个名字，如"美妆博主视频采集"
   - **选择平台**（必填）：下拉选择目标平台（抖音/小红书/B站/快手/微博）
   - **输入关键词**（必填）：每行一个搜索关键词，如：
     ```
     口红推荐
     底妆教程
     夏季护肤
     ```
   - **每词结果数**（可选）：默认 20，即每个关键词最多采集 20 个视频
3. **点击「创建并执行」按钮**

### 9.3 执行流程

```
[创建并执行]
    │
    ├─→ POST /api/lead-collector (action: create-task)  → 创建 CollectionTask 记录
    │
    └─→ POST /api/lead-collector (action: run-task)     → 触发采集执行
            │
            ├─→ engine-dispatcher.ts 分发
            │       │
            │       └─→ automation-providers.ts → MediaCrawler Python 进程
            │               │
            │               ├── douyinSearchVideo()     搜索并采集视频
            │               ├── douyinFetchComments()   采集视频评论
            │               ├── douyinVideoDetail()     补充视频详情
            │               ├── analyzeLeadIntent()     AI 分析评论意图
            │               └── extractContactInfo()    正则提取联系方式
            │
            └─→ 写入数据库: CrawledVideo + CrawledComment + Lead
```

### 9.4 运行状态监控

- 任务开始后，面板显示 **加载旋转动画**
- 仪表盘顶部出现 **脉冲动画提示**（蓝色闪烁点）
- 整个仪表盘 **每 5 秒自动刷新**一次数据
- 当所有任务完成后，脉冲消失，轮询停止

### 9.5 结果反馈

| 情况 | 显示 |
|------|------|
| 成功 | 绿色横幅："✅ 采集完成！新增 X 个视频，Y 条评论，Z 条线索" |
| 失败 | 红色横幅："❌ 采集失败：{错误原因}" |

### 9.6 注意事项

- ⚠️ **MediaCrawler 必须可用**：确保后台设置中 MediaCrawler 配置正确
- ⚠️ **Cookie 有效期**：Cookie 过期会导致采集失败，需重新扫码登录
- ⚠️ **频率限制**：高频采集可能触发平台反爬，建议合理设置间隔
- ⚠️ **关键词计数**：面板实时显示已输入的关键词数量

## 10. 筛选方案管理

**API 路径**: `/api/data-center/filter-presets`

### 10.1 功能概述

筛选方案允许将常用的**搜索+筛选条件组合保存为模板**，实现一键复用。适用于经常使用相同筛选条件的场景。

### 10.2 方案结构

```typescript
interface FilterPreset {
  id: number              // 唯一 ID
  name: string            // 方案名称（同一用户下同实体类型不可重名）
  description?: string    // 方案描述
  entityType: string      // 适用实体: video / comment / lead / user / trending
  filters: object         // JSON 格式的筛选条件，例如:
                          // { platform: 'douyin', minScore: 0.7, status: 'new' }
  isDefault: boolean      // 是否为默认方案
  isShared: boolean       // 是否共享（其他用户可见）
  userId: number          // 所属用户 ID
  createdAt: Date
  updatedAt: Date
}
```

### 10.3 CRUD 操作

#### 获取方案列表
```
GET /api/data-center/filter-presets?entityType=video&includeShared=true
```
- 返回当前用户在该实体类型的所有私有方案
- `includeShared=true` 时额外返回其他用户标记为共享的方案

#### 创建方案
```
POST /api/data-center/filter-presets
Body: { name, description, entityType, filters, isShared }
```
- 同一用户在同一实体类型下不可创建同名方案（返回 409 冲突）

#### 更新方案
```
PUT /api/data-center/filter-presets
Body: { id, name, description, filters, isDefault, isShared }
```
- 只有方案所有者可以更新

#### 删除方案
```
DELETE /api/data-center/filter-presets?id=123
```
- 只有方案所有者可以删除

### 10.4 使用场景示例

**场景 1：高价值抖音线索**
```json
{
  "name": "高价值抖音线索",
  "entityType": "lead",
  "filters": {
    "platform": "douyin",
    "minScore": 0.7,
    "status": "new"
  },
  "isDefault": true
}
```

**场景 2：美妆类小红书视频**
```json
{
  "name": "美妆小红书视频",
  "entityType": "video",
  "filters": {
    "platform": "xiaohongshu",
```

## 11. 定时采集调度

**API 路径**: `/api/data-center/schedule`

### 11.1 功能概述

定时采集允许为已有的采集任务**设置周期性自动执行**，无需人工每次手动触发。支持三种频率模式。

### 11.2 调度频率

| 频率 | 标识 | 最小间隔 | 适用场景 |
|------|------|---------|---------|
| **每小时** | `hourly` | 1 小时 | 高频热点监控 |
| **每天** | `daily` | 1 天 | 常规日常采集 |
| **每周** | `weekly` | 1 周 | 周报/周更内容 |

### 11.3 API 操作

#### 查看调度状态
```
GET /api/data-center/schedule
```
返回：
- 当前活跃的定时任务列表
- 内存中的调度器数量（Node.js Timer 数量）

#### 设置定时任务
```
POST /api/data-center/schedule?action=set-schedule
Body: { taskId: 123, frequency: 'daily', hour: 9, minute: 0 }
```
参数说明：
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| taskId | number | ✅ | 要定时的采集任务 ID |
| frequency | string | ✅ | hourly / daily / weekly |
| hour | number | daily/weekly 时必填 | 几点执行（0-23） |
| minute | number | 否 | 几分执行（0-59，默认 0） |
| dayOfWeek | number | weekly 时必填 | 周几执行（0=周日, 1=周一, ..., 6=周六） |

#### 立即执行
```
POST /api/data-center/schedule?action=run-now
Body: { taskId: 123 }
```
无视定时计划，立即触发一次采集。

#### 取消调度
```
DELETE /api/data-center/schedule?taskId=123
```
取消该任务的定时执行，不会删除原任务记录。

### 11.4 技术限制

> ⚠️ **重要**: 当前调度器基于 Node.js 内存中的 `setTimeout` / `setInterval` 实现。
>
> - **服务重启后丢失**: 所有正在运行的定时任务会在 Next.js 服务重启后清除，需重新设置
> - **单进程限制**: 仅在当前进程中生效，不跨实例同步
> - **后续优化方向**: 可迁移至数据库持久化 + 外部 cron 服务（如 node-cron + PM2）

### 11.5 使用示例

**示例 1：每天早上 9 点自动采集抖音美妆内容**
```bash
# 先创建任务
curl -X POST http://localhost:3000/api/lead-collector \
  -H "Content-Type: application/json" \
  -d '{"action":"create-task","name":"日采-抖音美妆","platform":"douyin","keywords":["口红推荐","底妆教程"]}'

# 假设返回 taskId = 42，设置每天 9:00 执行
curl -X POST http://localhost:3000/api/data-center/schedule \
  -H "Content-Type: application/json" \
  -d '{"action":"set-schedule","taskId":42,"frequency":"daily","hour":9,"minute":0}'
```

**示例 2：周一到周五每小时检查一次热搜**
```bash
# hourly 不需要指定 hour/minute，自动每小时整点执行
curl -X POST http://localhost:3000/api/data-center/schedule \
  -H "Content-Type: application/json" \
  -d '{"action":"set-schedule","taskId":55,"frequency":"hourly"}'
```

## 13. 常见问题

### Q1: 为什么采集任务一直处于 pending 状态？

**可能原因及解决方案**：
1. **MediaCrawler 未启动** → 检查后台设置中的 MediaCrawler 连接状态
2. **Cookie 过期** → 重新在设置页面扫码登录获取新 Cookie
3. **服务未触发执行** → 手动点击"立即执行"或在定时调度中触发

### Q2: 为什么没有数据显示？

请按顺序排查：
1. 是否已完成至少一次成功的采集任务？（查看仪表盘的采集任务表）
2. 当前页面的筛选条件是否过于严格？尝试清空所有筛选条件
3. 检查是否有对应平台的数据被采集过

### Q3: Cookie 多久需要刷新一次？

- **抖音**: 一般 3-7 天，频繁使用可能缩短至 1-3 天
- **小红书**: 类似抖音，约 3-7 天
- 建议：设置定时采集时关注任务执行结果，失败时优先检查 Cookie 状态

### Q4: 意向度评分是如何计算的？

系统内置 AI 意向识别引擎 (`analyzeLeadIntent`)，对每条评论进行 NLP 分析：
- 识别购买意向词汇（"多少钱"、"哪里买"、"怎么下单"...）
- 识别咨询意向词汇（"推荐吗"、"好用吗"、"链接"...）
- 识别紧急程度词汇（"急需"、"马上"、"越快越好"...）
- 综合输出 0~1 的意向度分数

### Q5: 联系信息是如何提取的？

系统使用正则表达式引擎 (`extractContactInfo`) 从评论文本中提取：
- **手机号**: 11 位中国大陆手机号格式
- **微信号**: 常见的 wx/xw/weixin 开头或纯字母数字组合
- **邮箱**: 标准 email 格式

### Q6: 服务重启后定时任务还在吗？

⚠️ **不在**。当前版本的定时调度器基于内存实现，Next.js 进程重启后所有定时器会被清除。需要重新设置定时计划。

**临时解决方案**: 重启后在仪表盘手动执行一次采集，然后重新设置定时任务。

### Q7: 可以同时运行多个采集任务吗？

可以。系统支持并发执行多个采集任务，仪表盘会同时显示所有 running 状态的任务，并在全部完成后停止自动刷新。

### Q8: 筛选方案可以分享给团队成员吗？

可以。创建方案时设置 `isShared: true`，其他用户在获取方案列表时传入 `includeShared=true` 即可看到共享方案。

### Q9: 数据量大了之后性能如何保障？

当前设计要点：
- 所有分页查询都带 LIMIT/OFFSET，避免全表扫描
- 聚合统计使用 Prisma `$queryRaw` 原生 SQL，效率较高
- 后续可考虑添加数据库索引（SQLite 支持 CREATE INDEX）

### Q10: 如何备份导出数据？

当前版本暂未内置导出功能。可以通过以下方式：
1. 直接复制 `prisma/data.db` SQLite 数据库文件
2. 使用 SQLite 客户端工具（如 DB Browser for SQLite）导出 CSV/SQL
3. 后续版本将增加内置的 Excel/CSV 导出功能
