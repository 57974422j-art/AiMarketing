## 二、发现的问题清单

### 🔴 高优先级（影响功能正确性）

| # | 问题 | 位置 | 说明 |
|---|------|------|------|
| H-01 | **fetch 缺少 credentials** | `digital-human/page.tsx:96` | `POST /api/digital-human` 训练提交时缺少 `{ credentials: 'include' }`，后端用 `getAuthFromHeaders()` 鉴权可能获取不到用户信息 |
| H-02 | **fetch 缺少 credentials** | `storage/page.tsx:23,38,47` | Storage 页面所有 fetch 均缺少 `credentials: 'include'`，包括上传、删除等操作 |
| H-03 | **digital-human 未使用全局 CSS 组件** | `digital-human/page.tsx` 全页 | 使用大量内联 className (`bg-white/5`, `rounded-xl`, `font-mono`) 而非项目统一的 `card-glass`, `btn-primary`, `input-dark`, `text-label` 等全局组件样式 |

### 🟡 中优先级（设计不一致）

| # | 问题 | 位置 | 说明 |
|---|------|------|------|
| M-01 | **Toast 实现不统一** | 多个页面 | digital-human 用自定义内联 Toast；storage/image-generator/video-edit 用 `@/components/Toast` 的 `showToast()`。应统一为后者 |
| M-02 | **Storage 页面 UI 风格陈旧** | `storage/page.tsx` | 使用简单的 `h1` + 手写按钮样式，与其他页面（live/digital-human）的 `text-mono-lg` header + `btn-primary/btn-secondary` 不一致 |
| M-03 | **Auth Hook 使用不一致** | 部分页面 | digital-human 未引入 `useAuth()` hook（无用户角色判断）；其他功能页面（image-generator/text-to-video/live）均使用了 `useAuth()` |
| M-04 | **返回值格式不完全统一** | 部分 API | 大部分 API 返回 `{ success, data, message }` 格式，但部分 API（如 `/api/media-library`）直接返回数组或不同结构 |

### 🟢 低优先级（建议优化）

| # | 问题 | 位置 | 说明 |
|---|------|------|------|
| L-01 | **孤立 API 未被前端直接调用** | ~20 个后端 route | 包括 `/api/accounts`, `/api/browser`, `/api/diagnose-network`, `/api/export`, `/api/fetch-prompts` 等。这些 API 可能被 admin 后台内部调用或作为工具函数存在，需确认是否为废弃代码 |
| L-02 | **数字人页面未做角色校验** | `digital-human/page.tsx` | 无 admin/editor/end-user 角色过滤，所有登录用户均可访问。对比 image-generator 有 authLoading 检查 |
| L-03 | **场景库加载无 loading 态** | `digital-human/page.tsx:62-67` | sceneLib 加载期间无骨架屏/loading 占位，空状态和加载态显示一致 |

## 三、各模块使用说明

### 3.1 数字人形象克隆 (`/digital-human`)

**功能**: 上传真人视频 → 克隆数字人形象 → 输入文案 → 生成口播视频

**操作流程**:
```
步骤 1: 选择克隆模式
├── 极速版 (fast): 约3分钟，适合快速测试
└── 精品版 (pro): 约24小时，高质量商用

步骤 2: 上传素材
├── 必填: 真人视频 (MP4/MOV/AVI, 最大200MB, 建议30-120秒正面露脸)
└── 可选: 录音音频 (用于声音克隆)

步骤 3: 提交训练 → 等待进度轮询 → 形象克隆完成

步骤 4: 口播视频生成
├── 输入文案 (支持中英文)
├── 选择背景:
│   ├── 纯色预设 (6种: 纯白/浅灰/商务蓝/墨绿/深空/暖橙)
│   ├── 自定义图片上传
│   └── 直播场景库 ← 从 prompt-templates 动态加载
└── 点击「生成口播视频」

步骤 5: 结果处理
├── 下载视频 (.mp4 直接下载)
├── 存入素材库 (→ storage，可用于直播推流)
└── 继续制作 (重置回到 generation 步骤)
```

**右侧面板**:
| 区域 | 内容 | 数据来源 |
|------|------|----------|
| 克隆说明/GUIDE | 操作指引卡片（静态） | 硬编码 |
| 直播场景/SCENE LIBRARY | 场景缩略图网格 | GET `/api/prompt-templates?category=场景` |
| 任务信息 | 训练时的 ID/状态/模式 | 动态状态 |

**关联模块**:
- → `/api/digital-human` — 训练提交 + 进度查询 + 视频生成
- → `/api/storage/save-digital-human` — 存入素材仓库
- → `/api/prompt-templates?category=场景` — 场景背景库

---

### 3.2 直播推流引擎 (`/live`)

**功能**: 组建播放列表 → FFmpeg 编码推流 → RTMP 直播到平台

**操作流程**:
```
步骤 1: 创建直播间
├── 选择平台 (抖音/快手/视频号/淘宝)
├── 绑定账号 (从已配置的社交账号中选择)
└── 可选绑定设备 (Q1手机/物理设备用于中控)

步骤 2: 组建素材
├── 方式A: 上传本地视频 → clips目录
├── 方式B: AI一键生成口播内容
│   ├── 选择风格 (专业/活泼/亲切/幽默)
│   ├── 选择产品 (从产品库选择)
│   └── AI 生成脚本 + 自动合成视频
└── 方式C: 从素材仓库导入 ← 闭环入口
    ├── 弹窗展示 storage 中视频列表
    ├── 多选文件
    └── 导入到当前播放列表(playlist)

步骤 3: 推流控制
├── 开始推流 → FFmpeg 启动 RTMP 编码
├── 暂停/恢复
├── 切换下一个 clip
└── 停止推流

步骤 4: 中控 (可选)
├── 评论自动回复 (规则匹配)
├── 商品讲解话术推送
└── 实时互动管理
```

**Tab 结构**:
| Tab | 功能 | 关键 API |
|-----|------|----------|
| 直播间管理 | CRUD 直播房间 | GET/POST/PUT `/api/live` |
| 推流控制 | FFmpeg RTMP 控制 | POST/GET `/api/live/stream` |
| 素材管理 | Clips 上传/删除/刷新 | 同上 |
| AI 内容 | AI 一键生成口播视频 | 同上 |
| 中控 | 评论/商品/话术 | `/api/live/command`, `/api/live/products`, `/api/live/scripts` |

**关联模块**:
- ← `/storage` — 从素材仓库导入视频 (import-from-storage)
- ← `/digital-human` — 数字人口播视频存入仓库后的来源
- ← `/prompt-templates` — AI 生成内容的提示词来源

### 3.3 素材仓库 (`/storage`)

**功能**: 用户个人视频/图片素材的存储管理中心，配额 500MB

**操作流程**:
```
┌────────────────────────────────────────┐
│  素材仓库                              │
│  配额: ████████░░ 320MB / 500MB       │
│                                        │
│  [+ 上传]  支持图片/视频                │
│                                        │
│  ┌────────┬────────┬────────┐          │
│  │ video1 │ video2 │ img1   │          │
│  │ 45MB   │ 32MB   │ 2MB    │          │
│  │ [推]   │ [推]   │ [推]   │          │
│  │ [删]   │ [删]   │ [删]   │          │
│  └────────┴────────┴────────┘          │
│                                        │
│  推送: 选择客户端设备 → 推送到Q1/指纹   │
└────────────────────────────────────────┘
```

**API 接口**:
| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/api/storage/files` | 列出文件 + 配额信息 |
| POST | `/api/storage/files` | 上传文件 (FormData) |
| DELETE | `/api/storage/delete?name=xxx` | 删除指定文件 |
| POST | `/api/storage/save-digital-human` | OSS URL 下载入库 (数字人专用) |
| POST | `/api/video/push-to-account` | 推送到指定客户端设备 |

**数据来源（写入端）**:
| 来源模块 | 入库方式 |
|----------|----------|
| digital-human | 生成完成后点「📦 存入素材库」→ 下载 OSS URL 写入 |
| text-to-video | 生成完成后保存到 media-library (带 category=场景) |
| image-generator | 生成完成后保存到 media-library |
| 手动上传 | 页面上传按钮 |

**数据去向（读取端）**:
| 目标模块 | 读取方式 |
|----------|----------|
| live 直播引擎 | 「📦 从仓库导入」弹窗 → importFromStorage() 复制到 clips |
| video-edit | 通过 media-library 间接引用 |

### 3.4 AI 文案 (`/ai-copy`)

**功能**: AI 批量生成多平台营销文案

**操作流程**:
```
输入产品/品牌信息
    ↓
选择目标平台 (小红书/抖音/朋友圈/公众号...)
    ↓
选择风格 (专业/活泼/亲切/幽默...)
    ↓
AI 生成 → 编辑调整 → 复制/保存
```

**关联**: 生成的文案可复制到 digital-human 作为口播文案，也可用于 text-to-video 的描述输入。

### 3.5 AI 图片生成 (`/image-generator`)

**功能**: 文字描述 → AI 生成图片

**操作流程**:
```
方式 A: 自由输入
├── 输入 prompt (中文/英文)
├── 选择尺寸 (1280*1280 / 1024*1792 等)
├── 选择模型 (auto/百炼/硅基)
└── 可选参考图

方式 B: 从模板库选取
├── 左侧: 提示词模板列表 (/api/prompt-templates)
├── 分类筛选: 海报封面/产品展示/品牌宣传...
└── 点击模板 → 自动填充 prompt

生成结果:
├── 预览大图
├── 下载
└── 收藏到媒体库 (media-library)
```

**右侧面板**:
- 模板库 (从 prompt-templates 加载)
- 我的收藏 (从 media-library 加载)

### 4.2 SOP 工作流映射

**内容生产 SOP（7步）**:
| 步骤 | 操作 | 对应页面 |
|------|------|----------|
| 1 | 行业洞察 | `/dashboard` 数据概览 |
| 2 | AI 文案生成 | `/ai-copy` |
| 3 | 数字人形象克隆 | `/digital-human` (upload → training) |
| 4 | 视频制作 | `/digital-human` (generation) 或 `/text-to-video` 或 `/video-edit` |
| 5 | 存入素材库 | digital-human 点「📦 存入素材库」→ `/storage` |
| 6 | 发布推送 | `/storage` → 推送到 Q1/指纹浏览器 |
| 7 | 数据追踪 | `/dashboard` 或 `/data-center` |

**直播运营 SOP（5步）**:
| 步骤 | 操作 | 对应页面 |
