# 「AI 直接成片」接入方案（2026-09-20）

> 用户指令：**「继续看 AI 直接成片怎么加，优先 MiniMax H3」**
> 一句话结论：**技术底座已存在**（`src/lib/minimax-h3.ts` 完整可用），要做的是**把它接进现成的成片链路**，而不是新造一套。

---

## 一、现状盘点（先说"已经有什么"）

### 1.1 已有的 AI 生视频能力

| 位置 | 能力 |
|---|---|
| `src/lib/minimax-h3.ts` | **★主角**：`generateH3Video(prompt, duration, resolution, ratio, refImageUrl?)` —— 异步提交+轮询（最长 600s）、**中转优先→官方降级**、支持图生视频首帧、`768P`/`2K`、**单段 4~15 秒**、返回 `videoUrl` |
| `src/lib/ai-providers.ts:2193` | `generateVideo(prompt, duration, resolution, ratio, model?)` —— **`model='h3'` 时走 H3**，失败降级百炼 `wan2.7-t2v` |
| `src/lib/ai-providers.ts:579` | `generateLongVideo(...)` —— **首尾帧接力**（长视频分段 + 尾帧续接，已解决收尾帧统一） |
| `src/lib/ai-providers.ts:2186` | 降级链：`Doubao-Seedance 2.0 → wan2.7-t2v → happyhorse-1.0-t2v → Mock` |
| `src/lib/ai-providers.ts:495` | `wan2.7-i2v`（图生视频） |

### 1.2 已有的成片链路（本次要接进去的地方）

```
前端 VF_FORM（画面来源/画幅/时长/音色/风格/BGM）
  ↓
chat/route.ts · make_ai_video
  → 生成分镜 shots[]（type: bgimage/title/list/number/compare/chart/end + src=图片路径）
  → plan = { size, fps, shots }
  → spawn: python3 make.py --plan <JSON> --script … --theme … --speaker … --bgm …
      ↓ tts.py   （逐镜配音 + 回填每镜真实时长 → storyboard.voiced.json）
      ↓ render.py（每镜渲染：Ken Burns 图片动效 + 大字 + 逐字字幕 → 拼接 → 烧字幕 → 混音）
  → 成片落 OSS + 入库个人仓库 + 前端完成卡
```

**关键**：`render.py` **只认识"图"**（`bgimage` 走 `zoompan` 推拉）。**"AI 生成"要新增一种镜头源：视频**。

## 二、方案：新增第 3 种镜头源 `aivideo`

### 2.1 三种画面来源的定位（不对用户用缩写）

| 画面来源 | 做法 | 成本（30 秒片） | 适用 |
|---|---|---|---|
| **素材合成**（现状） | 你上传/仓库的图 + Ken Burns 推拉 | **6 点**（按文案字数） | 有素材、要便宜、要快 |
| **素材 + AI 混合** | **部分镜头用 AI 生成**，其余用素材 | 中（按 AI 镜数算） | 关键镜要"动起来"，控制成本 |
| **全部 AI 生成** | **每一镜都调 AI 生视频** | **⚠️ 1500~2400 点** | 无素材、要电影感、不在乎成本 |

> ⚠️ 成本量级差异极大（**几十倍到几百倍**）→ **必须生成前报价 + 用户确认**（沿用现有"确认出片"卡）。

### 2.2 数据流（在现有链路上"插一步"）

```
make_ai_video 被调用（已确认）
  ↓
【新】若 source ∈ {ai, mix}：
    逐镜（或部分镜）调 generateH3Video：
      prompt = 分镜的英文画面描述（复用分镜生成时产出的 prompt 字段）
      duration = round(该镜配音时长)   ← 先跑 tts 拿真实时长，再按镜生成（见 2.4）
      落盘 → <workdir>/clips/shotNN.mp4
      shots[i].type = 'aivideo'；shots[i].src = <本地 mp4 路径>
  ↓
plan = { size, fps, shots }（结构不变，只是 type/src 变了）
  ↓
make.py → tts.py（不变）→ render.py
  ↓
【新】render.py 新增 aivideo 分支：直接铺该段视频（缩放裁到画布），不做 Ken Burns
```

### 2.3 render.py 要加的分支（小改动）

```
# 伪代码：render_shot 里 aivideo
ffmpeg -i clips/shot03.mp4 \
  -vf "scale=<W>:<H>:force_original_aspect_ratio=increase,crop=<W>:<H>,fps=25" \
  -t <该镜时长> -an shot03.mp4      # 音频由后面统一混音，这里先静音
```

要点：
- **时长对齐**：AI 生成的是整数秒（4~15），配音是小数秒 → **用 `tpad`/`loop` 补足或 `-t` 截断**（取"补齐"更自然，避免话没说完）
- **不做 Ken Burns**（视频本身在动，再加推拉会晕）
- **字幕照旧叠加**（逐字浮现 + 描边）—— 这是成片识别度的一部分
- **画幅不一致时**用 `force_original_aspect_ratio=increase + crop`（裁切而非拉伸）

### 2.4 ★关键设计：时长怎么对齐（这是最容易出错的地方）

**问题**：H3 单段支持 **4~15 秒整数**，而每镜配音是**小数秒**（如 7.2s）。
**两种策略**：

| 策略 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 先配音再生成**（推荐） | 先生成全部配音 → 拿到每镜真实时长 → **按每镜时长取整生成 AI 片段** → 渲染时 `tpad` 微调 | 音画对得上、不浪费 | AI 生成在配音之后（多等一步） |
| B. 先定死每镜时长 | 分镜时就把每镜定成整数秒，配音去适配 | 流程简单 | 配音被硬裁，语义可能断 |

→ **采用 A**。落地上 `make.py` 的顺序要调整为：**先跑 tts.py（拿时长）→ 再生成 AI 片段 → 再 render.py**。

### 2.5 计费与成本提示（★必须做，否则会"多扣费"重演）

- **H3 官方价**：`768P = 0.50 元/秒（50 点/秒）`、`2K = 0.80 元/秒（80 点/秒）`
- **计费口径**：`Σ 每镜实际生成秒数 × 单价`（H3 返回 `usage.output_seconds`，**精确到真实产出秒数**，可用它对账）
- **生成前必须**：把 `镜数 × 秒数 × 单价` 报到确认卡上（如"全部 AI 生成 · 6 镜 ≈ 36 秒 ≈ **1800 点**"）
- **降级时**要提示：H3 不通 → 自动降级百炼 `wan2.7-t2v`（价格/质量不同，**应在卡片上写明实际通道**）

## 三、落地步骤（分 3 步，每步可独立验证）

### 第 1 步：打通"全部 AI 生成"（最小闭环）
1. `chat/route.ts`：`VF_FORM.source` 增加 `'ai'`；确认卡加"全部 AI 生成"选项 + **成本报价**
2. `make.py`：`--source ai` 时，**先 tts 拿时长 → 逐镜调 H3 → 落 `<workdir>/clips/` → 改写 plan 的 type/src** → 再 render
3. `render.py`：新增 `aivideo` 分支（铺视频 + 裁画布 + 字幕）
4. **验证**：跑一条 2 镜短片（约 12 秒、≈600 点），看是否有画面 + 有声音 + 字幕在

### 第 2 步：混合模式
1. 表单加"**素材 + AI 混合**"；规则先做简单版：**首镜 + 末镜用 AI**（抓眼球 + 收尾），中间用素材
2. 或让 AI 在分镜时就标注 `need_ai: true` 的镜头（更适合"数据/对比"这类需要画面张力的镜）

### 第 3 步：质量与兜底
1. **失败重试**：某镜 H3 失败 → 该镜**自动回退成 bgimage（用素材图）**，不整片失败（沿用"未知卡型降级"的思路）
2. **通道透明**：卡片显示"本次画面来源：全部 AI 生成（H3·中转）"或"（H3·官方）"或"（降级 wan2.7）"
3. **成本对账**：用 H3 返回的 `output_seconds` 与实际扣点核对

## 四、开工前必须先确认的 2 件事（问用户）

1. **H3 通道配好了吗？** 需要后台「AI 密钥 → H3」填【中转地址+Key】**或** `MINIMAX_API_KEY`（官方）。
   —— 没配的话，第 1 步就要先验证通道（否则代码写完也跑不出画面）。
2. **"全部 AI 生成"的价格预期**：30 秒片约 **1500~2400 点**（而素材合成只要 6 点）。
   —— 确认可接受再开工，避免做完发现"太贵不用了"。

## 五、风险与护栏（沿用现有 12 条护栏的思路）

| 风险 | 护栏 |
|---|---|
| **多扣费**（刚修过一次） | 生成前报价 + 按 `usage.output_seconds` 对账 |
| AI 生成失败致整片失败 | **单镜失败 → 回退 bgimage**（用素材图顶上），不整片挂 |
| 生成太慢（每镜 100s+） | 600s 上限已有；**镜数 × 时长要设上限**（如 ≤8 镜）并在卡片提示"约需 N 分钟" |
| 音画不同步 | 策略 A（先配音后生成）+ 渲染 `tpad` 补齐 |
| 内容敏感被拒 | H3 返回 `failed` 时**不降级**（`minimax-h3.ts` 已实现）→ 该镜回退素材图 |
| 画幅不对 | `force_original_aspect_ratio=increase + crop` |
| 通道不明 | 卡片显示实际通道（中转/官方/降级） |

---

## 六、结论

- **不需要新造轮子**：`generateH3Video` + `generateVideo(model='h3')` + 降级链 + 首尾帧接力**都已存在**
- **要做的就 3 处**：① `route.ts` 加 `source='ai'` + 报价 ② `make.py` 插"先配音→再生成"一步 ③ `render.py` 加 `aivideo` 分支
- **最大风险是成本**（1500~2400 点/条 vs 素材 6 点）→ **报价 + 确认必须放在最前面**
- **最大技术坑是时长对齐** → 用"先配音后生成 + tpad 补齐"
