2. 判据（每一帧上现在有两个独立信号）
============================================================
屏幕内容 =  【整帧纯色】 + 【顶部小方框 "T<第几秒>"】 + 【居中大号数字 = 该秒内的帧号 0..24】

(a) 颜色 -> 判定落在【第几秒】：
    第0秒 #C00000 红 / 第1秒 #00A000 绿 / 第2秒 #0000C0 蓝 / 第3秒 #E0A000 琥珀
    第4秒 #8000A0 紫 / 第5秒 #00A0A0 青 / 第6秒 #606060 深灰 / 第7秒 #A0A0A0 浅灰
(b) 居中大号数字 -> 判定落在【该秒内第几帧】（帧级！）：
    期望值 = round(t * 25) mod 25        （t = 外层组合的时间轴时刻）
    例: t=1.10 -> 27.5 取 27/28 -> 秒内帧 2/3   实测=3
        t=1.90 -> 47.5 取 47/48 -> 秒内帧 22/23 实测=23
        t=1.5  -> 37.5 取 37/38 -> 秒内帧 12/13
    ⚠️ ±1 帧的不确定性来自抽帧命令的 -ss（落在帧边界上取整），不是 seek 误差。
    容忍度: 数字与期望相差 <=1 帧 -> 帧级对齐 PASS；相差 >=3 帧 -> 记为偏移量并报出。
(c) 失败模式区分（洋红诊断底）：
    整帧洋红 #FF00FF -> 视频【根本没加载】（先查素材路径/file://，不是 seek 问题）
    整帧纯黑          -> video 元素有尺寸但【没解出画面】（用 codec-check.cjs 复核编解码器）
    颜色/数字是邻近的别的秒 -> 真·seek 偏移（记录偏移量）

4. 用法（两条都要遵守, 否则测的是别的东西）
============================================================
(a) 素材与 HTML 必须放在 **HyperFrames 项目目录内**（相对路径引用），本包已把两者放在同一层,
    并用 <video src="probe-seek.mp4"> 这种"同层相对路径"写法规避"项目根相对 vs 文件相对"的歧义。
    file:// 绝对路径会被浏览器拦截 -> 渲染日志出现 [media_load_failed]（REPORT.md §4 坑③）。
(b) 视频**故意不 loop**：loop 会把"seek 错位"掩盖成"看起来正常"。
    若把 3 秒素材塞进 8 秒组合, t>3 画面是洋红 —— 设计如此, 不是 bug。

5. 本包版本变更（v2 修了我自己的一个真 bug, 请用 v2）
============================================================
v1 的标签是坏的: 帧上显示 "T=220" 而不是 "T1"（字体也变小了）。
根因: PowerShell 双引号串里写 "text=T$i:fontsize=220" —— PS 把 `$i:fontsize` 解析成
      "scope i 下的变量 fontsize" -> 下标 $i 被吃掉, "=220" 并进了 text。
修法: 一律写成 "text=T${i}"（用花括号界定变量名）。**.sh 版不受影响**（bash 的 $i 后面
      跟 ':' 会正常结束变量名）, 但为对称也已改成 ${i}。
v2 另加了居中大号 %{n} 帧计数器 -> 判据从"秒级"升级为"**帧级**"。

6. ⚠️ 另一个重要发现: HyperFrames 产物的色彩标签与现有渲染层不同
============================================================
本机基线渲染产物 baseline-win-3s.mp4 的 ffprobe:
    color_range=tv  color_space=bt709  color_transfer=bt709  color_primaries=bt709
而源素材 seek-test/probe-seek.mp4 与现有渲染层 old.mp4:
    color_range=unknown  color_space=unknown  ... （全部 unknown / 无标签）
-> 同一帧画面（源角落 RGB 0,161,0）在 HTML 线产物里解码成 (0,133,0) —— 色矩阵/范围解释不同。
-> 影响: concat -c copy 拼接时, 各段自带自己的色彩标签, **播放器基本按整条文件/首段解释**,
   HTML 段(bt709/tv) 与现有段(无标签)混拼可能出现**色差**。拼接方案需明确要不要统一
   `-color_range/-colorspace` 或统一重编码。
（见 REPORT.md §7.8）
