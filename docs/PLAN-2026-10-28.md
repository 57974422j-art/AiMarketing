# 日报落地页（AI 自由设计线）· 现状与升级规划

> 日期：2026-10-28
> 适用：`日报落地页`（daily）+ `HTML 成片`（htmlfilm）两条共用 `VfFilmCard` 的线
> 本文只做**规划**，不含已完成的历史修复清单（那些在 `ISSUES.md` 与 git log 里）

---

## 一、一句话定位

> **不是"套模板出片"，是"让 AI 每次重新做一次设计"。**
> 代价是稳定性靠打磨，收益是每单长得不一样、文字绝对精确。

竞品坐标（2026-10 实查）：

| 项目 | 路线 | 和我们的差别 |
|---|---|---|
| **html-video**（Open Design，Apache-2.0） | 同用 HyperFrames，**21 套模板**，吃文章/链接 | 他们靠**模板**保稳定；我们靠**自由设计**换新颖 |
| Remotion / Motion Canvas | 代码即视频（人写 React） | 页面是人写的，不是 AI 写 |
| Shotstack / Creatomate | 云渲染模板 API | 版式固定，换素材不换设计 |
| Sora / 可灵 / 即梦 | 扩散模型生成像素 | **汉字会糊、不可控、不可复现** —— 不是同一条路 |

⇒ 我们的位置：**"实拍素材 → AI 自由设计 → 精确文字"**，这条路公开项目很少（因为难）。

---

## 二、现状（用户实测口径，2026-10-28）

| 指标 | 实测 | 说明 |
|---|---|---|
| **一次成功率** | **≈95%** | 比早期 80% 明显提升；失败集中在"口播与图片偶发不对应" |
| **单条耗时** | 3~4 分钟（思考 open）/ ~2 分钟（save） | 用户体感"整体吐一条约 10 分钟"含渲染与出片 |
| **成片水准** | "昨天做的几条水准其实很高，有的画了图形" | 说明**代码画图形**这条路已经跑通 |
| **成本** | "已经几乎极致" | 一次文本调用 + 本地渲染，无单次生成费 |

⇒ **结论：主体已经能用，剩下的都是"更稳、更好、更懂你"。**

---

## 三、已知缺陷（按严重度）

| # | 缺陷 | 严重度 | 根因（已查证） |
|---|---|---|---|
| **1** | **画面文字只有 2 种字体** | 🔴 高（最影响"高级感"） | 项目只内嵌 `NotoSansSC-sub.woff2` / `NotoSerifSC-sub.woff2` 两个子集，提示词写死 `TXT-Serif` / `TXT-Sans` |
| **2** | **口播与图片偶发不对应** | 🟠 中高 | 段是"一次生成 + TTS 回填时长"，AI 看图定段序；偶发错位**没有校验** |
| **3** | **没有经验积累** | 🟠 中高 | 每次从零开始：不记用户改了什么、不记哪种设置好用 |
| **4** | **成片资产不留档** | 🟠 中 | 只有 `gen_xxx.html` + `gen_xxx.mp4`，**没有"成品库"**，也没有可复用的参考素材 |
| **5** | **口播连贯性弱** | 🟡 中 | 逐段独立写（不是先整篇再切）；用户已明确"后面能改就行"，**暂不修** |
| **6** | **动效密度不稳定** | 🟡 中 | 已加"这是视频不是海报"提醒，但**未验证**效果 |

## 四、升级规划（按性价比排序）

### 【P0】字体扩容 —— 最快见效的"高级感"提升

**现状**：只有 2 个中文字体（黑 / 宋），且各 1MB 子集。

**为什么现在能做了**：`daily-film.mjs` 已把内嵌 base64 **外置成 `assets/` 文件**（★VF_DAILYFILM_V8），单文件版不再被字体撑爆 ⇒ 体积压力大幅下降。

| 做什么 | 加 3~5 个字体，覆盖常见设计需求 |
|---|---|
| 建议字体 | ① 思源黑体 **Bold / Light**（同族不同字重最像"专业设计"）<br>② 阿里巴巴普惠体（商用免费、字重全）<br>③ 霞鹜文楷（文艺/餐饮手写感）<br>④ 一个**粗黑**（促销/强冲击） |
| 提示词改法 | 把「只能用 Serif/Sans」改成「**标题三选一**（宋/黑粗/文楷），正文黑体」+ 说明各自气质 |
| 体积代价 | 每个子集约 **0.8~1.5MB**（子集化后）；因为已外置，只影响 `assets/` 目录 |
| 花费 | **1.5~2 天**（含子集化脚本、提示词、验证） |
| 收益 | ⭐⭐⭐ 直接解决"文字太少/太单调"这个最大观感问题 |

---

### 【P1】成片资源库 —— 每单成品都留档（用户新提）

**现状**：成品只有两个文件（html + mp4），**没有"作品库"概念**，也不能被后续复用。

**要做什么**：

```
每单出片完成后，往「作品库」写一条：
  · 成品：gen_xxx.html（单文件版）+ gen_xxx.mp4
  · 元信息：素材指纹、主题、段数、时长、tier/thinkMode、生成日期、用时
  · 缩略图：第一帧（已有 .thumbs 机制）
  · 可选：口播全文、画面字全文（结构化 JSON）
```

**用途（这些是后续三年的地基）**：

| 用途 | 说明 |
|---|---|
| **回溯** | "上个月那条好的长什么样" —— 不用翻 OSS 目录 |
| **参考片** | 挑一条满意的当"风格样本"（见 P2） |
| **对比** | 同一批素材不同设置的产出并列看 |
| **训练素材** | 提炼风格包、AB 偏好数据，全靠它 |

| 项 | 说明 |
|---|---|
| 做什么 | 新表 `dailyArtifact`（或复用 `VideoTemplate`）+ 出片完成时写入 + 后台一个列表页 |
| 花费 | **2 天**（表 + 写入 + 列表页）<br>**+1 天**（详情页：预览 html / 播 mp4 / 看口播全文） |
| 收益 | ⭐⭐⭐ 不直接提升单条质量，但**是所有学习机制的前提** |

---

### 【P2】学习机制：风格包闭环 —— "培养成高级动效剪辑师"

**好消息：实验室（`/admin/vf-studio`）已经有一半**：

```
已有：参考视频 → extract-elements → 生成风格包（styles/<id>.json）→ /api/render 试片
风格包字段：mood / speed / tokens(色板) / structure(页型) / elements(元素)
            motion{ enter, emphasis, exit, pace }  ← ★动效语言
            prompt(一句话风格描述)
```

**缺的两段桥**：

| 缺 | 做什么 | 花费 |
|---|---|---|
| **① 成品 → 风格包** | 解析日报成品的 HTML，提取：主色板、字号分布、用到的元素（网格/大字/线/贴纸）、**动效类型与每段数量**、段长节奏 ⇒ 存成 `styles/daily-<ts>.json` | **2~3 天** |
| **② 风格包 → 提示词** | 素材卡加下拉「参考风格：[无] / [我保存的…]」；选中就把风格包转成一段"倾向"注入 `aiDesignPrompt` | **1 天** |

**口径（必须守住）**：

```
风格包教的是"倾向"（底色偏冷 / 动效偏密 / 节奏偏快）
版式仍然每次由 AI 自己想
⇒ 不是模板，不限制发挥；默认"不选 = 一个字不变"
```

| 项 | 说明 |
|---|---|
| 总花费 | **3~4 天**（两步） |
| 收益 | ⭐⭐⭐ 这是唯一能让它"越做越像你"的机制 |
| 前提 | **必须先有 P1 的作品库**（否则没有"满意成品"可提炼） |

---

### 【P3】口播与图片对齐校验 —— 治那 5%

**现状**：AI 看图定段序，TTS 回填时长；**没有任何"这段说的和图对不对"的校验**。

**做法（低成本）**：

```
出页前加一道轻校验：
  对每一段：用一次**很小的**多模态调用（或复用已有的视觉描述 descMap）
  判断「这段 voice 提到的东西，这张图里有没有」
  ⇒ 全片只做一次批量判断（不是 16 次调用）
  ⇒ 明显不匹配的段落，让 AI 换图（不改文案）
```

| 项 | 说明 |
|---|---|
| 花费 | **1.5~2 天** |
| 收益 | ⭐⭐ 把 95% 往 98% 推 |
| 风险 | 多一次调用（约 +10~20 秒）；判断本身也可能错 ⇒ **只告警 + 自动换图，不改文案** |

---

### 【P4】动效密度验证（零成本，只需测）

**现状**：已加「这是视频，不是海报」提醒（含"≥两种属性一起变"），但**没验证过**。

| 做什么 | 量同一批素材改动前后的 `var(--p)` 使用次数 / 每段动效种类 |
|---|---|
| 花费 | **0.5 天**（写个统计脚本） |
| 收益 | ⭐ 只是确认"提醒有没有用"；没用就换更强手段（给参考片段） |

## 五、明确"不做"（避免反复讨论）

| 不做 | 原因（用户已定案） |
|---|---|
| **加模板兜底** | "HTML 那边已经有模板，我不想限制 AI 发挥" |
| **整篇口播稿 → 切段** | "后面能改就行，既要又要很难达到" |
| **字幕逐字变色（卡拉OK）** | TTS 无字级时间戳，误差 0.2~0.5s 且累积；换 ASS 挂了整片没字幕 |
| **数字人 / 素材生成** | 不是我们的定位，成本 10 天+ |
| **可视化 Studio** | 自用不值；现有卡片编辑够 |
| **降到模板保稳定** | 与"AI 自由设计"的核心取舍冲突 |

---

## 六、建议执行顺序

```
第 1 步（2 天）    P1 成片资源库 ──── 所有学习的地基
第 2 步（2 天）    P0 字体扩容   ──── 立刻改善观感（可并行）
第 3 步（3~4 天）  P2 风格包闭环 ──── 越做越像你
第 4 步（2 天）    P3 图口对齐校验 ── 治那 5%
第 5 步（0.5 天）  P4 动效验证    ─── 确认提醒有没有用
────────────────────────────────────
合计约 9.5~10.5 人天
```

⇒ **P0 + P1 可以并行**（互不依赖），**P2 依赖 P1**，P3/P4 独立。

---

## 七、一句话总结

> **主体已经能用（95%），剩下的不是"能不能出片"，是"像不像专业剪辑师做的"。**
> **最快的提升是字体（P0），最长远的是成片库 + 风格包（P1→P2），最直接治短板的是图口对齐（P3）。**
> **不做模板 —— 那条路和"AI 自由设计"是互斥的。**
