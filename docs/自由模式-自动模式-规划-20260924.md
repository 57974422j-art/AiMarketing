# AGENT「自由模式」规划（会话式现场执行）— 2026-09-24

> 状态：**规划稿，未施工**。目标是把 AGENT 页的「自由模式」做成"你说一句话，它自己去网页上办事"的能力。
> 铁律：**标准模式一个字不动**（它是保底可用方案，两者必须完全隔离）。

---

## 一、目标与非目标

### 目标（按可落地程度排序）

| 档 | 任务形态 | 举例 | 结论 |
|---|---|---|---|
| **档 1** | 纯读取/收集 | "打开这个网址，把前 10 条标题抄下来" | ✅ 可行，最值得先做 |
| **档 2** | 读取 + 填表，**停在付款/提交前** | "在淘宝找到 X、比价、加购物车并填好地址，停在下单前问我" | ✅ 可行（推荐形态） |
| **档 3** | 全自动下单 + 支付 | "帮我买张机票然后付掉" | ❌ **不做**（见下） |

### 非目标（明确不做，省时间）

1. **不做自动支付** —— 钱、退款、责任都在你身上，必须人工点。
2. **不做"AI 全程跑发布"** —— 40 步连乘，单步 95% → 成功率 13%，**结构性失败**（已用两周验证过）。
3. **不动标准模式**，不与它共用任何状态。
4. **不做高危站点全自动**（电商/票务的风控与法务风险 > 收益），这类站点只做档 1/档 2。

## 二、为什么现在"自由模式不能现场执行"——五个真实断点（含证据）

| # | 断点 | 证据（路径:行号） | 后果 |
|---|---|---|---|
| 1 | **默认标准模式锁死自由文本** | `src/app/agent/page.tsx:1100`（默认 `'standard'`）；`src/lib/agent/standard-commands.ts:37-53`（11 条必须一字不差）；`src/app/api/agent/chat/route.ts:2211-2235`（未命中且无流程 → 直接固定话术） | 任意指令在门口被拒 |
| 2 | **browser_use_execute 是 admin 专属** | `scripts/seed-agent-tool.cjs:9-16`（`roles:'admin'`）；`route.ts:2167-2170`（按角色过滤）；`route.ts:2181`（`EXCLUDE_FREE` 又排除发布类） | 普通登录用户**没有浏览器执行通道** |
| 3 | **模型 key 不下发给普通用户** | `src/app/api/agent/browser-config/route.ts:9-10`（非 admin 403）；`electron/main.js:1822`（把空 key 传给 Python）；`scripts/browser-use/bu_exec.py:16-20`（回退到开发机路径 `D:\AiMarketing\.env.local`） | 用户机上 bu_exec 直接失败 |
| 4 | **bu_exec 只会"发布抖音"** | `scripts/browser-use/bu_exec.py:207`（`MANUAL='发布这个视频到抖音…'`）、`:221`（`extend_system_message=MANUAL`）、`:174`（内置平台 URL）、`:220`（`use_vision=False` 硬编码） | 传进自由任务也按发布手册走 |
| 5 | **没有"问人"通道** | `electron/main.js:1666-1840`（checkBrowserTasks 全程无 dialog/暂停）；`route.ts:1316-1328`（建任务无确认） | 卡住只能死循环或失败；**不会问你** |

### 附：三个"看着像能跑其实跑不通"的细节

- 自由模式提示词要求"发布必须调 `browser_use_execute`"（`src/lib/agent/prompts.ts:21`），但该工具是 admin 专属 → **自相矛盾**。
- 自由模式的对话历史与标准模式**共用**（`route.ts:2115` 取最近 10 条；`prisma/schema.prisma:1054-1074` 会话表**无 mode 字段**）→ 上下文互相污染。
- 自由模式下 `hasDraft` **未按模式门控**（`route.ts:2334/2339`）→ **标准模式残留的草稿会让自由模式的回答被吞掉**（这就是"总留尾巴"的典型）。

## 三、施工规划（含阶段 0 与止损线）

> 原则：**先用最小代价证明"行不行"，再投入架构。** 每阶段都有可验收的判据。

### 阶段 0｜最小可行性验证（半天，先不写架构）

- **做法**：不动 AGENT 页，命令行直接跑一次"打开某网站 → 执行一句简单任务 → 报告结果"。
- **用例（3 个）**：① 打开某站读一个数字；② 在搜索框输入并搜索；③ 点开第一个结果并总结。
- **Go / No-Go**：
  - 3 个用例过 2 个以上 → 继续投；
  - 连最简单的都过不了 → **停**，别投隔离与护栏。

### 阶段 A｜彻底隔离（1 天，收益最大）

| 要切断的共享点 | 具体改法 |
|---|---|
| 会话/历史 | 会话加 `mode` 字段（或用独立会话）；客户端切模式时**不共用** `sessionId/history`（`page.tsx:2189`） |
| 进行中流程/草稿 | 给 `pub_draft`/`vf_draft` 打 mode 标签；**自由模式不读不写**（`route.ts:2255-2258`、`2334/2339`） |
| 工具过滤 | 判据统一（`route.ts:2181` 同时判 `mode` 与 `agentMode`）；自由模式给一份**独立工具集** |
| 提示词 | 从单函数参数分叉，拆成 `free-flow.ts` / `standard-flow.ts` 两个文件（`prompts.ts:8-9` 已有此规划） |
| 护栏预留 | 为阶段 C 预留"问人"回传通道（服务端 + `main.js`） |

**验收**：自由模式里发"帮我把这条发抖音"，它**完全不知道发布流程的存在**（不恢复草稿、不出现发布卡片、不引用任何标准模式规则）。

### 阶段 B｜给它"眼睛"和"纪律"（2~3 天）

- **眼睛**：打开 `use_vision`（`bu_exec.py:220` 现为 False）；把**可点元素清单 + 坐标 + 遮挡关系**喂给模型（即"点前用 `elementFromPoint` 判该点最上层是不是它自己"）。
- **纪律（写成代码，不靠提示词）**：
  - 危险动作黑名单：付款/提交订单/删除/退出/解绑/设置横封面…**一律禁止**；
  - 点前复验遮挡；点后复验结果；
  - **没验证成功不许报成功**（教训：快手"没点中却报发布成功"）。

### 阶段 C｜让它会问你（2 天，**命门**）

- 执行中遇到"看不懂 / 要登录 / 要验证码 / 多个候选" → **暂停并抛回会话**；
- 你在会话里回一句 → 它继续（`main.js:checkBrowserTasks` 增加"等待中"状态与回传通道）；
- **没有这一层，自由模式必然重演两周前的失败。**

### 阶段 D｜定生死（1 天）

- 三个真实任务：① 查价格 ② 加购物车不付款 ③ 查机票不买；
- **判据**：档 1/档 2 成功率 ≥ 80% → 继续；< 70% → 退回"AI 只兜底一步 + 脚本执行"的小形态。

## 四、架构定论（写在最后，避免走偏）

```
用户永远只说一句话
        ↓
系统内部路由：熟路 → 脚本（快/稳/省/可群控）
              生路 → browser_use 现场执行（慢/贵/但什么都能干）
        ↓
现场执行成功后 → 把关键选择器/时序【写回配置】→ 下次走快路径（自愈沉淀）
```

**对外只有"一句话入口 + 一张结果卡片"，用户不该知道这次走的是脚本还是 AI。**

## 五、成本与安全（必须一起考虑）

| 项 | 现状 | 建议 |
|---|---|---|
| 模型 key | `browser-config` 把 `DASHSCOPE_API_KEY` **下发到客户端**（`main.js:1822`） | **改为服务端代理**（或短期/限额/绑设备的临时凭证）—— 客户端持明文 key 等于对外泄露 |
| 成本 | 一次 40 步任务按 token 计 | 定位为"长尾/兜底"，高频固定流程仍走脚本 |
| 速度 | 每步 1~3 秒推理 | 同上；不要拿它替代 20~40 秒的脚本发布 |

## 六、给未来的自己：三条最容易踩的坑

1. **别用提示词治纪律** —— 提示词是建议，代码才是保证（"没点中不许报成功"必须写在代码里）。
2. **别让 AI 做"信息不足的坐标猜测"** —— 给它遮挡信息与可点清单，比调提示词有用 10 倍。
3. **每次兜底成功都要沉淀** —— 不沉淀就永远"每次从零开始"，这就是"呆板"的根源。
