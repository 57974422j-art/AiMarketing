# 设想：配音稿卡片「看画面 + 让 AI 重写这段」

> 记录于 2026-10-23。**只是设想，未实现**。
> 来源：用户实际使用中提出（编辑人员需要"看着画面"才能判断文案怎么改）。

---

## 1. 要解决什么

现在第 4 步（配音稿）卡片上只有文字：

```
段 3 · 17/22 字 · ~3.8s
冰盘锁住虾的脆甜，看着就爽
```

编辑**看不到这一段画面上是什么样**，只能凭记忆判断"这句话配那张图合不合适"。

⇒ 想在编辑某一段时**同时看到那一帧的截图**。

---

## 2. 交互（已确认的样式）

**一个弹窗**，上下三段：

```
┌──────────────────────────────────────┐
│  第 3 段                              │
│  ┌────────────────┐                  │
│  │                │  ← 这一帧的截图   │
│  │  （720×1280）   │   （编辑能看见     │
│  │                │    画面长什么样）  │
│  └────────────────┘                  │
│                                       │
│  现在的文案：                          │
│  ┌────────────────────────────────┐  │
│  │ 冰盘锁住虾的脆甜，看着就爽      │  │  ← 可直接手改
│  └────────────────────────────────┘  │
│                                       │
│  想让 AI 怎么改？                      │
│  [钩子] [折扣] [口语] [更狠] [自定义…] │
│  ┌────────────────────────────────┐  │
│  │（点上面按钮，这里自动填好）      │  │
│  └────────────────────────────────┘  │
│                                       │
│  [ 🤖 让 AI 重写 ]  [ 保存 ]  [ 取消 ] │
└──────────────────────────────────────┘
```

### 关键点
- **不是两个弹窗**：看画面 + 改文案 **在同一个弹窗里**；
- 图在上面、字在中间、AI 入口在下面；
- AI 生成后**先填进输入框**，人再决定要不要保存（不直接落库）；
- 「保存」才写回草稿。

---

## 3. 技术上怎么落

| 部分 | 做法 | 难度 | 耗时 |
|---|---|---|---|
| **弹窗界面** | 前端一个 modal（图 + textarea + 按钮组） | 低 | — |
| **拿这一帧的图** | 服务端调 `hyperframes snapshot --at <该段起点+一半>` 抽一张 PNG，返回 URL | **中** | **8~12 秒** |
| **AI 重写文案** | 一次小请求（带：这段文案 + 视频主题 + 该段素材的画面描述） | 低 | 2~3 秒 |
| **保存** | 改草稿里该段的 voice 文本 | 低 | — |

### 让体验变好的做法
- **预抽帧**：进第 4 步时，后台把 14 段的帧**一次性抽好缓存**（多等 20~30 秒）⇒ 点弹窗时**图已经在**，零等待；
- **按段缓存**：段没改就不重抽。

---

## 4. 为什么不做"拖动改字号"

编辑看到的是**截图（位图）**，不是网页 ⇒ 拖动它不会动。

真要做"拖一下就生效"，必须：

```
打开真实网页 → 识别"你点的是哪块" → 实时改 CSS → 重新截图
```

⇒ 那是 **openfilm Studio** 那种编辑器的活儿（独立产品量级），**暂不做**。

**折中（以后可考虑）**：给**滑块**而非拖拽——选"改哪一块"（标题第一行/第二行/信息点/小字）+ 字号 ×倍 / 位置 ±px / 颜色。每次调整重抽一帧（10 秒）。

---

## 5. 前置条件（先修这个，弹窗才有意义）

**现在画面上的大字和配音稿是两套文案**（两次独立生成）：

```
画面大字：黄转盘摆满肉盘        ← AI 写 HTML 时写的（描述画面）
配音稿  ：清汤配手切肉，鲜掉眉毛  ← AI 看素材图另写的（卖点）
```

⇒ 编辑在弹窗里看着"黄转盘摆满肉盘"这张图，改的却是"清汤配手切肉"这句口播 ⇒ **两边对不上，会越改越乱**。

**必须先做**：让配音稿**照着画面文字展开**（把每段"画面写什么"传给 `aiVoicePrompt`，要求围绕那句写口播）。

---

## 6. 优先级建议

| 步 | 做什么 | 为什么先做它 |
|---|---|---|
| **1** | 配音稿照画面文字写（改一句提示词） | 不修这个，弹窗里"图"和"字"是两回事 |
| **2** | 弹窗（图 + AI 重写 + 保存） | 编辑日常 80% 的调整就是"这句话不好" |
| **3** | 滑块微调（字号/位置/颜色） | 等 2 稳定后再做 |

---

## 7. 一个要记住的约束

**改文字不需要渲染；看效果需要渲染。**

| 操作 | 要服务器渲染吗 | 耗时 |
|---|---|---|
| 改文字 / AI 重写 | ❌ | 秒级 |
| 看这一帧 | ✅ | 8~12 秒（可预抽缓存） |
| 整片重出 | ✅ | 60~90 秒 |
