## 三、C 模式（不限时长）讨论稿

### 3.1 现在的模型（说明"不限时长"不是一个开关）

```
用户选时长(30/60/…) → 文案字数 = 时长×4.5 → 镜数 ≈ 时长/5
                        ↓
   tts.py 逐镜合成配音 → **回填每镜真实时长** → render.py 按"配音时长"渲每一镜
```
⇒ 所以让"3 分钟素材整段播完"，本质是**要让视觉轨不再被配音切段** —— 这就是你说的"硬合并"，也是必须引入"**画布/时间轴**（双轨）"的原因。

### 3.2 路线 1：硬合并（你说的那种）

**定义**：视觉轨 = 素材按原长首尾相接；成片时长 = Σ素材时长（3 段 3 分钟素材 → 9 分钟片）。
要补三件事：**画布统一** / **配音怎么办** / **字幕怎么办**。

| 配音方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **1A 静音原声** | 这几镜不放配音，只用素材原声（或全静音） | 最省事、素材"原汁原味" | 全片没口播（营销片通常要一句人声） |
| **1B 按时长重写文案** | 让 AI 按"素材总时长"重写文案 → 配音念满整片 | 有口播、节奏自然 | **要动文案长度**（等于放弃"你选的时长"），配音时长≠素材时长仍会有偏差 → 末尾留白或截断 |
| **1C 你给的文案 + 留白/原声补足** | 文案照念，念完就静音留着画面走 | 保留你的文案 | 观感"话音落画面还在走"，需要字幕配合 |

### 3.3 路线 2：双轨（画布/时间轴）—— 更通用的解法

把「镜」从"配音段落"里解耦：

```
视觉轨：clip1(180s) | clip2(95s) | 图(4s) | …      ← 各段用各自的真实长度
音频轨：配音 / BGM / 原声（可重叠、可空缺）
字幕轨：按"念到的句子"打时间点（不再绑镜）
```
**影响面**（这是它贵的原因）：`render.py`（镜结构 + 音画对齐）、`tts.py`（不再按镜切段，改按"句/段"切）、`make.py`（组装）、分镜提示词（不再受 4.5 字/秒约束）、确认卡（时长/成本估算改成"预计成片时长"）、前端表单（时长选项语义变化）。

### 3.4 我建议的**最小可用版 C1**（不改架构，先能用）

只做一种场景：**"长视频整段用"**

1. 表单加一档 **「不限时长（按素材原长）」**（或在"图视混剪"里加选项）；
2. 分镜规则：这几镜 `vstart=0`、`dur=素材原长`、**不裁不切**；顺序默认按素材名/用户排序；
3. **画布统一**：沿用 `VF_SIZEFIT_V1`（横竖混排时统一到多数比例 + 模糊填充，**不裁切**）；
4. **配音：先按 1C**（你给的文案照念、念完静音、画面继续走；字幕按句子打完）；
5. 硬保护：单条素材 >30 分钟 / >400MB 不进（`VF_VIDGUARD_V1` 已有）；成片总时长超阈值（如 10 分钟）给确认提示。

代价：`chat/route.ts`（表单与确认卡）、`vf-video.ts`（分镜规则）、`make.py`/`render.py`（"素材原长"与"音画不等长"的兜底）。**不改 tts 的分句模型** ⇒ 风险可控。

### 3.5 需要你定的 7 件事

1. **配音**：1A 静音原声 / 1B 重写文案念满 / 1C 你的文案念完就静音？（我建议 1C，之后可切 1B）
2. **是否允许 AI 裁掉素材中段**？（C 模式=不裁；要裁就走 A 模式）
3. **顺序**：文件名顺序 / 你手动排 / AI 排？
4. **字幕**：还要不要？要的话按"句"打点可以吗？
5. **总时长上限**：设多少（10 分钟？20 分钟？）—— 渲染耗时与失败重试成本随长度线性上升；
6. **横竖混排**：统一到多数比例 + 模糊填充（推荐）／还是要求素材先自己统一？
7. **原声**：3 分钟素材里有说话/音乐时，原声留不留（留 = 会和配音叠在一起）？

## 四、成片"简陋"方向规划

### 4.1 家底盘点（其实不薄）

| 已有 | 说明 |
|---|---|
| **9 种配方卡** | title / list / number / image / video / compare / chart / quote / aivideo |
| **逐镜（分段）渲染** | 改一镜只重渲那一镜（抄 video-talkcraft） |
| **"list 一项=一步"** | 已抄 garden-skills 的逐步揭示铁律 |
| **主题 token（最小集）** | `{bg, text, accent, font}`；表单 3 套：深蓝科技 / 深青科技 / 浅色纸感 |
| **画布自适应** | `VF_SIZEFIT_V1`（不放大、不糊） |
| **门禁/兜底** | 覆盖率门禁、字幕兜底、扩镜、切段限长、低清过滤、素材抽样、示例词清理、JSON 容错 |

### 4.2 我判断"简陋"的 6 个成因

1. **实际用到的卡型太单一**：素材合成线基本就是 `bgimage + title` 循环 → 观感=「图 + 大字」重复 N 遍，像图文轮播；
2. **主题 token 太薄**（只有 4 个）：没有"标题/正文/角标"的层级、字重、间距、圆角、阴影体系 → 每张卡靠默认值，**没有设计感**；
3. **素材本身不美**（你自己说的：深色界面截图）→ 任何模板都救不回来，得靠"素材体检 + 更好的兜底卡"；
4. **运动语言单一**：几乎每镜都 Ken Burns —— 而反 AI 味清单里明确写着 ✗「每步都挂 ken burns」；
5. **没有"样板镜先确认"**：用户看到成品才发现风格不对（**这是成本最高的一条缺口**）；
6. **AI 味元素没有代码级黑名单**：渐变背景 / emoji 当图标 / 假数据 / 右下角 mono 角标 等，全靠提示词自觉。

### 4.3 可借鉴的方法（出处都在 `docs/成片工作流方案-借鉴开源研究.md`）

| 方法 | 出自 | 对我们的用法 |
|---|---|---|
| **首镜先做先确认**（先出 8 秒样板镜给用户点头再量产） | video-talkcraft | **P0**：出一镜预览再出整片（尤其"图视混剪"） |
| **反 AI 味清单**（黑名单：紫粉渐变/圆角卡片+彩边/渐变药丸/emoji 当图标/假数据/每步 ken burns/右下角角标） | garden-skills | **P0**：写进分镜提示词 + 做一层渲染前校验 |
| **主题 token 体系**（23 套主题的做法） | garden-skills | P1：把 token 从 4 个扩到"排版/层级/间距/字重/动效曲线"，3 套 → 6~8 套 |
| **逐步揭示**（讲 X 亮 X；讲 Y 时 X 灰化保留） | garden-skills | P2：`list/number/compare` 三张卡的节奏细化 |
| **运动做减法**（每场只留一条极缓推拉） | video-talkcraft | P2：关掉"每镜都 ken burns"的默认 |
| **缺就承认缺**（用 placeholder 占位卡，不用 emoji/无关图凑） | garden-skills | P2：无合适素材 → 出"设计过的文字卡"，而不是硬塞截图 |
| **分段渲染只重渲变更段** | video-talkcraft | P3：已有逐镜渲染，可加"只重渲第 N 镜"的入口 |
| **唯一真相源**（防多处漂移） | garden-skills | P3：分镜 JSON 作为唯一真相源（已在用） |
| **硬性自检协议**（产出必须过检才汇报） | 三家共同 | 已在用（门禁/覆盖率），可扩到"画面黑名单自检" |

### 4.4 分档方案

| 档 | 内容 | 预期效果 | 代价 |
|---|---|---|---|
| **P0** | ① **样板镜先确认**（先出 1 镜 mp4 预览，用户点头再出整片）② **反 AI 味清单**落地（提示词 + 渲染前校验） | 最直接治"简陋"：不会再"整片出来才发现不对"；画面不再出现典型 AI 味元素 | 小（卡片多一步 + 提示词/校验） |

## 附录 A：本次已做 —— 文字排版修复（★VF_TEXTFIT_V2，2026-09-28）

用户实测原话：「**现在插入的文字看着怪怪的**」。定位到三个根因（都在 `scripts/video-factory/render.py`），已全部修掉：

| 根因 | 老行为 | 新行为 |
|---|---|---|
| ① **逐字浮现会左右漂移** | 每个前缀都 `x=(w-text_w)/2` 重新居中 → 字一边出现一边左右移动（像在抖） | **整块居中 + 未出现的字用表意空格 U+3000 占位** → 块不动、字在块内从左往右亮（底衬也不会从窄到宽地长出来） |
| ② **长句一路缩字号** | `fs = min(fs, W*0.86/字数)` → 长句字很小、短句字很大，**同一条片里大字忽大忽小** | **先折行（最多 2 行，`fit_big_text`）**，真放不下才缩字号（有下限） |
| ③ **字幕硬切** | 按 18 字 `txt[i:i+18]` 切 → 数字/英文/词被切断，断得怪 | **优先在标点处断句**（每行 ≤16 字、最多 2 行，`wrap_subtitle`） |

**像素级验证**（本机真跑 `render.py --selftest`，再抽帧测文字边缘）：
```
修前：左沿一直 263 不动，但收尾整行中心 604  vs 画布中心 640 → 偏左 36px（估宽偏大）
修后：t=1.4/2.0 文字中心 634 vs 画布中心 640 → 偏差 6px；块始终居中、不再漂移
9 种卡型自检全过（title/bgimage/aivideo/list/number/compare/chart/quote/end）
```
另外纠正一次我自己的误判：**字幕字号本来就按画布自适应**（`max(26, H*0.042)`），不是"写死 26"。
