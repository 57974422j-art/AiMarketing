## 一、背景：用户的要求与已完成的改动

**用户要求**：个人仓库里「成片」与「原始素材」要分开；**所有"自动成片"只读「原始素材」**（因为成片目录里资料乱，会污染选材）。
用户原话：「我有让改过，不知道改了没有」。

**查证结论：改了，主线全覆盖。**

| 日期 | 事项 | 证据 |
|---|---|---|
| 2026-10-11 | `VF_REPOSPLIT_V1` 仓库分家：成片改用 `gen_` 前缀、独立序号 | `src/lib/repo-naming.ts`（文件头 + `GEN_PREFIX = 'gen_'`） |
| 2026-10-12 | `VF_REPOSPLIT_V1b` 仓库页切换按键 + 老成片判据 | `src/app/api/storage/files/route.ts` |
| 2026-10-12 | ★`VF_MATONLY_V1`：**AGENT 取素材只认原始素材**（用户定案） | `src/lib/agent/video-material.ts`（`listRepoMaterials` 的过滤链）+ `chat/route.ts` 的清单两处 |
| 2026-10-12 | 日报落地页 v5：仓库只取原始素材 | `src/lib/agent/daily.ts` |

### ⚠️ 认知纠正（很重要，别按错误前提去改）

**"分开"不是分成两个目录，而是"同一平铺目录 + **文件名前缀**"**：

```
storage/{uid}/
  ├─ 20261008_013.jpg        ← 原始素材（无前缀）→ 自动成片只吃这类
  └─ gen_20261016_081.html   ← 成片（gen_ 前缀）→ 自动成片排除这类
```

**为什么不开子目录**（`repo-naming.ts` 文件头已论证）：会碎在三处 ——
① 文件下载接口的正则**禁 `/`**；② 删除接口同款；③ **客户端本地镜像用 `path.basename` 会把目录静默剥掉**。
⇒ **结论：用前缀分类是对的，不要改回目录方案。**

## 四、硬边界

1. ⚠️ **会碰 `video-material.ts`（7 条线共用咽喉）** ⇒ 这是"改一处、全线受影响"的操作 ⇒ **单独窗口、改完立即回归 7 条线**；
2. ⚠️ **不要给"用户上传素材"这条路新增过滤条件** —— 上传的片**不打 `gen_` 前缀**，回取是"按名单精确匹配 + 最近上传回退"（grep `上传名单在仓库里都没找到`）⇒ 一旦加条件，会出现"上传的文件找不到"的**静默回退**；
3. **不要真的去开子目录**（见第一节的论证）；
4. **不要扩大成"只允许某前缀"** —— 当前口径是"**排除成片**"，不是"白名单"。改成白名单会误杀上传件与老素材；
5. **`readOutcomeNames()` 依赖 `video-factory/vf*.json`**：该目录不可读时会**一条都不排**（老成片重新混入）⇒ 若顺手加固，要**打日志**，别静默。
